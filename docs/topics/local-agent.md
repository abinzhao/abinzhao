# 本地优先的 AI Agent 应用

本地优先意味着状态和业务数据的保存位置、读取范围与导出方式可控。使用远程模型时，请求中的内容仍然发送给模型提供方；只有本地模型和受控工具链才能满足更严格的不离端约束。

## 目标与结构

产物是一个解决具体任务的 Agent 原型：接收明确目标、读取允许的输入、提出工具调用、执行有限步数并返回有证据的结果。先选择一个只读任务，例如整理用户指定目录中的 Markdown 标题，再添加写操作。

```text
目标与允许目录 → 编排器 → 模型适配器（明确数据出口）
                   │
                   ▼
                工具校验 → 权限判断 → 执行
                   │
                   ▼
               本地记录与评测
```

模型输出是待校验的数据，不能直接获得终端、文件系统或外部系统的任意执行权限。

## 阶段一：界定数据与模型边界

阅读 [Agent 基础与数据边界](../tutorials/ai-agent/foundations.html)。记录输入、保存目录、模型连接方式、保留策略和网络出口。BYOK 让用户选择模型凭据，但并不自动解决数据隐私。

验收：用户知道哪些内容被发送、哪些仅保存在本地；没有把凭据写入浏览器代码、执行记录或日志；远程模型不可用时，任务保留可恢复状态。

## 阶段二：建立有限工具集

阅读 [工具调用与权限](../tutorials/ai-agent/tools.html)。每个工具定义参数、输出、错误与副作用。目录权限要在解析真实路径后验证；超时、调用步数和输出大小有明确上限。

验收：非法参数、越界路径、不存在的文件和超时都被拒绝并留下可解释记录。对写文件、发送消息和发布动作，模型建议不能替代用户授权。

## 阶段三：完成编排与恢复

将模型返回的工具请求转换成统一事件，在校验之后执行。保留任务 ID、调用顺序、状态与必要结果；输出过大的结果截断前保留引用。对于不可重复的副作用，恢复时不盲目重试。

验收：断网、工具报错和进程中断后，能够辨认最后一个已完成步骤；不把“模型说成功”作为任务成功依据。结果需要引用实际读取或生成的内容。

## 阶段四：建立评测与回归

阅读 [评测与可靠性](../tutorials/ai-agent/evaluation.html)。用固定任务、边界案例和权限拒绝案例观察行为。测试夹具要说明是教学案例，不能将演示样例当作真实产品效果统计。

验收：不同模型或提示版本运行同一组任务时，有可比较的记录；准确性、完成率、成本和越权行为分别检查；修改工具后重新验证受影响任务。人工判断与机器断言要各自说明范围。

## 完成检查

- 任务目标、数据来源与出口明确。
- 工具入参、路径和副作用有独立校验。
- 超时、步数、输出和恢复策略可观察。
- 凭据与敏感内容不进入日志。
- 评测区分教学样例与真实统计。

可以用 [Node CLI](../tutorials/nodejs/tools.html)、[Rust CLI](../tutorials/rust/cli.html) 或 [Python 自动化](../tutorials/python/automation.html) 实现工具层，按实际团队和运行环境选择。
