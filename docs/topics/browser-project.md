# 浏览器插件从开发到发布

完成一个最小扩展，比一次申请所有浏览器权限更容易理解各执行环境。这个专题以 Chromium 的 Manifest V3 为范围；迁移 Firefox 或其他浏览器时，按目标平台文档核对后台和 API 差异。

## 目标与执行边界

产物是一个可从浏览器扩展管理页加载的工具：用户明确触发操作，内容脚本读取所需页面信息，后台处理消息，弹窗显示结果与错误。

```text
弹窗（用户触发） → 后台 service worker
                         │ 消息
                         ▼
                    内容脚本
                         │ DOM
                         ▼
                     当前网页
```

网页、内容脚本、后台和弹窗拥有不同生命周期。后台 worker 可随时停止，不能靠全局变量保存长期状态；内容脚本能访问 DOM，但不能把网页输入当作可信指令。

## 阶段一：了解浏览器与清单

阅读 [浏览器导航与渲染](../tutorials/browser/architecture.html) 和 [扩展架构与权限](../tutorials/browser-extensions/fundamentals.html)。清单声明入口、后台和必要权限；区分 `permissions` 与 `host_permissions`。

验收：浏览器能加载目录；清单没有错误；权限与功能一一对应；对于不支持的页面，用户看到明确反馈。

## 阶段二：实现消息与存储

按 [实现一个浏览器插件](../tutorials/browser-extensions/implementation.html) 完成消息往返。定义消息类型、校验入参、返回明确成功或错误结果。持久状态写入扩展存储，在读写失败时展示恢复提示。

验收：弹窗关闭后状态仍可恢复；后台停止并重新唤醒后功能仍工作；标签页关闭、消息接收端不存在、权限不足时不会静默失败。避免把任意网页消息转成具有更高权限的操作。

## 阶段三：在真实页面调试

阅读 [DevTools 性能诊断](../tutorials/browser/debugging.html) 和 [扩展调试与发布](../tutorials/browser-extensions/delivery.html)。分别检查弹窗、worker 和内容脚本的控制台；修改清单或后台之后重新加载扩展，需要时也刷新标签页。

验收：普通网页、单页导航、空内容和特殊浏览器页面均有可解释的行为。通过浏览器工具查看实际消息、请求和存储；不要只检查构建成功。

## 阶段四：整理发布包

去除开发日志、调试入口和不需要的文件，检查资源都在包内。文档说明读取哪些信息、保存在哪、是否有远程请求。商店提交需要账号、截图与目标平台审核，生成 ZIP 只代表本地打包完成。

验收：使用发布 ZIP 解压后的目录重新加载，关键路径正常；权限说明与实际行为一致；没有动态执行远程代码；没有密钥或开发地址。

## 完成检查

- 清单、权限与目标功能匹配。
- 消息输入校验和错误返回清晰。
- worker 重启和弹窗关闭不破坏状态。
- 浏览器限制页面有恢复说明。
- 发布包与隐私说明经过核对。
