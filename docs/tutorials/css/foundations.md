# CSS 基础机制：选择器、层叠与盒模型

CSS 出现“写了但没生效”时，常见原因不是浏览器忽略代码，而是规则没有匹配、声明被层叠覆盖，或者你把最终尺寸理解错了。理解这些基础机制，可以让调试从不断增加选择器和 `!important`，转变为检查可解释的证据。本篇用一张阅读卡片逐步分析匹配、冲突、继承和尺寸，建立后续布局的共同模型。

## 前置知识与适用范围

先理解 [HTML 文档结构](../html/document.html)，能够创建元素、类名和外部样式表。练习只需要浏览器与文本编辑器，不使用框架或构建工具。创建独立目录，入口是 `index.html`，样式是同级 `styles.css`，直接打开入口即可。

本文采用常见现代浏览器长期支持的基础 CSS，并使用层叠层与 `:where()` 说明现代组织方式。目标环境若包含较旧浏览器，应先查这些特性的兼容表；不支持层叠层的浏览器可能忽略相应规则块，不能把它当成无影响的注释。本文不指定所谓最新版本，也不讨论所有浏览器默认样式差异。

## 选择器如何确定规则作用范围

选择器负责选中元素，声明负责改变属性。类选择器适合表达复用样式，例如 `.note`；后代选择器表达祖先关系，但范围太宽时容易影响深层内容。子代组合符只匹配直接子元素，有助于把规则限制在组件拥有的结构上。属性选择器可以描述现有状态或语义，不必为所有情况都额外发明类名。

伪类描述状态或关系，例如 `:hover`、`:focus-visible` 和 `:first-child`。伪元素描述元素中的特定部分或生成内容，例如 `::before`。生成内容适合装饰，不应承载读者必须获得而 HTML 中没有的关键业务信息。悬停也不是唯一入口，触屏设备没有可靠的持续悬停状态，键盘用户需要自己的焦点反馈。

选择器越长不一定越准确。把页面 ID、容器类和控件类层层拼接，会提高后续覆盖成本。样式规则如果只需要描述一张卡片的标题，使用简单且范围明确的类通常足够。只有 DOM 结构关系确实重要时，才依赖组合符；否则一次无关容器调整就可能使规则失效。

## 层叠与继承为什么不是同一件事

多个匹配声明竞争同一个属性时，层叠决定胜者。应先判断来源与重要性，再看层叠层、选择器优先级，最后在条件相同的情况下看源码顺序。不是所有“后写的样式”都能覆盖前面的样式。本文只创建作者正常声明，避免把整个规则算法简化成一个无法处理重要声明和动画的口诀。

在同一来源、相同重要性与同一层中，可以把常见优先级理解为 ID、类或属性及伪类、元素及伪元素的分组比较。它不是把数字凑成十进制后任意相加；很多类也不能简单“进位”成一个 ID。`:where()` 内部的选择器贡献为零，适合定义容易覆盖的基础规则。

继承发生在没有更合适的自身声明时，常见继承属性包括颜色和字体，而边距、边框通常不继承。一个低优先级直接选中子元素的颜色声明，也可以覆盖从父元素继承的颜色，因为继承不是与子元素声明继续比赛的高优先级规则。遇到字体未传给按钮时，应检查该控件的默认样式，并按需求显式声明 `font: inherit`。

层叠层让样式优先关系与选择器长度部分分离。正常声明中，后声明的层通常高于前层，未分层的正常作者样式又高于分层样式。重要声明的层顺序会反转，这是为了保护较早层的关键规则；不要把普通层顺序直接套用到 `!important`。实际工程应尽量通过清晰组织减少重要声明，而不是依赖它修补所有冲突。

## 第一步：创建可观察的样式冲突

把下列代码写入 `index.html`。两张卡片结构相同，第二张增加强调类；页内按钮只是一个原生控件，用来观察字体与焦点样式，不承担未实现的业务提交。

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>CSS 机制实验</title>
    <link rel="stylesheet" href="./styles.css">
  </head>
  <body>
    <main>
      <h1>CSS 机制实验</h1>
      <article class="note">
        <h2 class="note-title">普通笔记</h2>
        <p>规则先匹配元素，再决定声明的胜负。</p>
      </article>
      <article class="note note-featured">
        <h2 class="note-title">重点笔记</h2>
        <p>强调样式来自明确的修饰类。</p>
      </article>
      <button type="button">聚焦样式观察按钮</button>
    </main>
  </body>
</html>
```

再写入 `styles.css`。基础层中故意使用更高优先级的标题选择器，组件层用更简单的选择器覆盖它。这能观察“先比较层，再比较层内优先级”的结果，不需要靠肉眼猜测规则顺序。

```css
@layer base, components;

@layer base {
  * { box-sizing: border-box; }
  body {
    margin: 0;
    color: #182235;
    background: #f5f7fb;
    font: 1rem/1.75 system-ui, sans-serif;
  }
  main { width: min(100% - 2rem, 44rem); margin: 2rem auto; }
  main .note .note-title { color: #8a2525; }
  :where(button) { font: inherit; }
}

@layer components {
  .note {
    width: 100%;
    padding: 1rem;
    margin-block: 1rem;
    border: 2px solid #b4c4df;
    border-radius: 0.75rem;
    background: white;
  }
  .note-title { margin-block: 0 0.5rem; color: #174ea6; }
  .note-featured { border-color: #174ea6; }
  .note > p { margin-block: 0; }
  button { padding: 0.5rem 1rem; min-height: 44px; }
  button:focus-visible { outline: 3px solid #174ea6; outline-offset: 4px; }
}
```

打开入口，预期两个标题都为蓝色，而不是基础层声明的红色。第二张卡片的边框颜色不同。正文继承 `body` 的字体与颜色，按钮通过明确继承获得一致字体。按 Tab 可以看到按钮焦点；这也是检查规则匹配的一种实际状态，不能只检查静态截图。

## 第二步：用盒模型解释宽度

标准内容盒模型中，`width` 指内容区宽度，外侧还要加内边距和边框。`border-box` 中，指定宽度通常包含内容、内边距与边框，因此更适合“这张卡片整体放进容器”的思考方式。外边距仍在边框之外，不会因此被包含。使用开发者工具的盒模型视图可以分别查看这些值。

在 `styles.css` 末尾追加下面的实验规则，然后观察卡片。它以 320 像素为上限，同时保证窄屏不超过容器。由于使用 `border-box`，总边框盒宽度是 320 像素时，内容宽度会扣除两侧内边距和边框。默认字号为 16 像素时，计算是 320 减 32 再减 4，得到 284；如果字体基准变化，应按实际计算样式重新计算。

```css
@layer components {
  .note {
    width: min(100%, 320px);
  }
}
```

把 `box-sizing` 暂时改为 `content-box` 再观察，可以看到内边距和边框额外扩张。这个改动只是实验，完成后恢复原设置。布局中“宽度明明是百分之百却溢出”，常常与这种额外尺寸有关，但也可能来自长字符串、最小内容宽度或固定宽度子元素，不能只凭症状认定一个原因。

普通块布局里的垂直外边距在特定条件下会折叠，并不总是相加。内边距不会像外边距那样折叠。Flex 和 Grid 项之间可以使用 `gap` 表达间距，降低边距相互作用的复杂度，但并不意味着所有边距都应替换成 `gap`。先判断间距属于容器内项目关系，还是元素与外部上下文的关系。

## 检查结果与错误排查

在样式面板选择标题，预期看到红色声明被划掉、蓝色声明有效，并能看到所属层。只看最终计算值能知道结果，查看匹配规则才能解释原因。临时在开发者工具取消某条声明，可验证假设；这些临时编辑不会自动保存到文件，最终修改仍要回到源样式。

如果规则完全没有出现，检查类名、样式文件路径和选择器关系。如果规则出现但被覆盖，检查来源、层和优先级，不要立即增加 `!important`。如果值被标记为无效，检查单位、拼写和属性允许的值。浏览器遇到无效声明往往忽略该声明，其他声明仍可能继续工作，因此页面不会必然整体报错。

如果卡片宽度不对，分别读取内容宽度、内边距、边框和外边距，再检查父容器可用空间。如果按钮字体不同，检查浏览器控件规则而不是重复调整正文。长链接撑开容器时，可以按需求使用 `overflow-wrap: anywhere`，但不要把正常正文设置成逐字任意断行来掩盖结构问题。

## 指定值、计算值与实际尺寸

样式表里的声明是指定意图，计算样式会解析继承、相对单位和变量，布局阶段还要依据可用空间得到使用尺寸。因此一个百分比宽度可能在样式面板里仍显得抽象，盒模型面板却能显示当前实际像素尺寸。截图测量、声明文本和布局结果不是同一层证据，调试时应说清楚正在比较哪一种值。

相对单位也有不同参照。`rem` 通常依据根元素字号，`em` 在不同属性上依据相关字体尺寸，百分比则由具体属性定义参照关系。不要认为所有百分比都相对父元素宽度，尤其是高度、变换和间距规则需要各自确认。选择单位应服务于阅读与空间关系，而不是统一把所有像素机械改成同一个单位。
