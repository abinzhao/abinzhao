# 02 前端工程化

<p class="content-lead">
当页面开始增长，仅靠几个脚本文件很快会失去秩序。这个阶段把类型、组件、依赖、构建和测试组合成稳定的工程工作流。
</p>

## 本阶段目标

你将从模块化源码走到用户可以操作的页面，再为正确性和交付质量建立证据。
重点不是收集框架 API，而是回答：状态由谁拥有、外部数据何时可信、资源何时释放、失败如何恢复。
每节都给出文件路径、完整示例、预期效果、失败修复和验收练习，建议边运行边解释机制。

完成后应能独立实现一个带表单、浏览器路由和异步目录的 React 应用。
也应能用完整 Vue SFC 表达计数与过滤，说明它和 React 在状态写入、依赖追踪上的差异。
最后用行为测试、键盘操作和资源加载记录验收，而不是仅凭“页面能打开”判断完成。

## 前置知识与工具

先完成[前端基础](../frontend-basics/)，至少掌握以下能力：

| 前置能力 | 自测方式 | 不熟悉时先补什么 |
| --- | --- | --- |
| HTML 与表单语义 | 能给 input 关联 label，并选择正确 button 类型 | label、form、提交事件 |
| CSS 与布局 | 能解释盒模型、宽度约束和焦点样式 | 响应式容器、focus-visible |
| JavaScript 数据处理 | 能用 map/filter 处理对象数组而不误改原数组 | 引用、复制、闭包 |
| 异步与异常 | 能用 async/await、try/catch 检查 HTTP 与 JSON | Promise、fetch、异常分支 |
| 浏览器开发工具 | 能找到失败请求、控制台异常和当前 URL | Network、Console、Elements |

安装 Node.js 22.12+ 的 22.x 或当前 Vite 支持的 LTS；模板演进时核对官方 engines，不猜版本要求。
选 npm 或 pnpm 中的一种负责安装，固定锁文件；两个管理器命令不同，不要在同一项目交替安装。
编辑器需要 TS 支持，Vue 可安装官方 Vue 扩展；编辑器没有报错仍不等于终端类型检查通过。
准备浏览器键盘操作和开发者工具，不要求真实后端、数据库或云服务账号。

## 示例的运行约定

本目录是教程文档，不是需要执行安装的应用根目录。
所有安装、类型检查、测试和示例构建命令，都在自己创建的练习项目内运行。
不要修改教程主站依赖或在主站执行示例构建，也不要把练习代码直接粘进文档主题目录。

| 练习项目 | 创建位置与来源 | 如何使用 |
| --- | --- | --- |
| tooling-lab | 第 1 节 vanilla-ts 模板 | 第 2 节替换 HTML 与源码，保留 TS 配置 |
| react-lab | 第 3 节 react-ts 模板 | 各节替换自己的 App，保留明确说明的模板文件 |
| vue-lab | 第 6 节 vue-ts 模板 | 使用该节完整 HTML、入口与 SFC |

代码组标签就是文件路径，`public/`、`src/` 和根目录配置不可放错层级。
高亮行标出机制重点，不表示只写这些行；需要使用整个代码块及它引用的配套文件。
没有提供的模板文件需按正文要求保留，不能删掉 TS 配置、Vite 插件或挂载节点。
章节切换会替换 App；保留自己想比较的版本可用 Git 提交，避免把多个默认导出粘到同一个文件。

先核对版本和脚本：

```bash
node -v
npm -v
npm pkg get scripts
```

`npm pkg get scripts` 必须在练习项目中执行；后续命令以该清单为准。
Vite 负责转换和打包，不替代完整 TS 检查；脚本是否包含 `tsc` / `vue-tsc` 需要实际核对。
本教程不保证未来 latest 模板永远相同，第一次运行后保留锁文件，才能复现自己的验证结果。

## 建议的学习方法

每节先运行原始完整例子，记录页面文字、操作路径和控制台结果，再修改一个条件。
接着复现正文中的失败，例如无效配置、非法 JSON、下标 key、失效邮箱或未清理定时器。
观察失败证据后修复，重新走相同操作；这个过程比仅背诵“最佳实践”更能建立机制理解。
最后完成练习，以验收条件判定结果，不通过删断言、关闭检查或吞异常制造成功。

记录时区分三类证据：类型检查验证静态关系，行为测试验证输入输出，浏览器验证实际交互与资源。
同一个问题可能需要组合证据。例如请求竞态需要快速切换测试，而错误字段类型需要边界校验。

## 阶段项目与验收

把 React 章节组合成“学习目录”应用，采用以下范围，不要求接入真实账号系统：

1. 首页显示说明，目录页读取 public JSON，邮箱页完成受控验证。
2. URL 驱动三个页面，支持直达、普通链接、后退/前进和未知页兜底。
3. 请求有加载、成功、空目录、错误与重试；快速切换和卸载不会提交旧结果。
4. 可选复习面板按需加载，提供等待、失败恢复、关闭与焦点返回。
5. 给验证规则写单测，给表单写 RTL 行为测试，给导航及关键提交流程写 E2E。

组合时明确文件职责：App 管路由与页面选择，validation 管纯规则，Catalog 管请求，Review 管复习交互。
不要把模板、所有教程 App 和三套入口同时堆入一个文件，也不要为了练习建立通用状态框架。
Vue 对照项目单独验收：计数正确、过滤更新、computed 不承担请求、自动计时开关与卸载均清理。

| 验收面 | 可观察的完成标准 |
| --- | --- |
| 依赖与类型 | 一份锁文件；安装可复现；明确的类型检查命令通过 |
| 边界与状态 | 错误 JSON 可读反馈；排序不串备注；表单编辑清除旧成功 |
| 生命周期 | 快速切换只显示当前目录；隐藏组件后无遗留请求/定时器 |
| 路由 | 地址与页面一致；后退/前进、直接刷新及兜底有证据 |
| 测试 | 正常版本通过；有意破坏行为时相关断言真实失败 |
| 交付与体验 | 练习项目产物独立预览；键盘路径完整；分包请求时机可观察 |

性能验收需记录测量条件，不把一次本地 LCP 或 TBT 写成线上 P75 已达标。
静态托管的路径回退和缓存响应头由实际服务配置决定，没部署就标记未验证。
不用 screen reader 验证时，也不能宣称 ARIA 朗读已在所有辅助技术上通过。
