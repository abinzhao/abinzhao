# 第 12 章：图像、字体、音频与 glTF 资源流水线

素材能够在编辑器显示，并不代表导入参数、目标平台和许可都正确。资源流水线需要把可编辑源文件转成运行时资源，并保证更换机器、重新导入和导出后仍能得到相同含义。本章不要求购买素材；毕业项目本身只使用原生几何图形与程序生成音频，导入实验可使用自己创作且有明确权利的文件。

## 12.1 源文件和缓存不是一回事

把图像放入项目后，引擎读取源文件并按导入设置生成内部资源。`.godot` 主要承载本地缓存和编辑器状态，不是美术源文件；与源文件关联的导入描述记录选项和映射。资源应通过原始项目路径加载，而不是依赖某次机器生成的缓存文件名。

首次打开或源文件变化时会重新导入。缓存删除后可以从源重建，不意味着可以删除源文件和导入设置。跨机器重建失败时，先确认源文件是否完整、导入参数是否保留、所需外部工具是否安装，再检查缓存。只复制缓存会使问题隐藏到下次导入或导出。

运行中的 Image、ImageTexture、Mesh 和 AudioStreamWAV 也属于 Resource，但不一定经过磁盘导入器。毕业项目的声音由脚本建立，墙体使用 Polygon2D，这解释了为什么它不依赖外部素材。程序生成资源需要自己的尺寸与内存预算，不能认为没有图片文件就没有资源成本。

## 12.2 建立可追溯目录

素材少时按用途建立 textures、audio、fonts、models 即可；复杂项目再按关卡或角色组织，不要提前设计庞大的分类框架。文件名表达用途与来源，避免把 final、final2、newest 当成版本管理。保存许可说明、作者与原始来源，发布时才能准确完成告知。

编辑步骤是先把自有文件放进 FileSystem 可见的目录，等待扫描，选中文件，在 Import 面板查看类型和参数，再点 Reimport。每次只调整一组参数，打开实际场景比较效果。运行时引用用资源路径或可靠 UID，不使用操作系统上的绝对个人路径。

改名和移动优先通过编辑器 FileSystem，让相关依赖一起更新。外部移动后若出现缺失资源，应检查场景、脚本和导入映射，不要把所有引用改成数字缓存路径。迁移素材前记录使用者，迁移后运行所有相关场景，不能只确认文件树中名字变了。

## 12.3 纹理采样与像素风

纹理尺寸决定原始细节，过滤决定放大或缩小时如何采样。像素风通常需要 nearest，平滑绘画通常使用 linear；Godot 4 的二维过滤由 CanvasItem 或项目默认设置控制，不应照搬旧版“在图片导入面板勾选 Filter”的教学步骤。父节点的继承关系也会影响子图表现。

Mipmap 是逐级缩小的纹理链，远距离或缩小显示时能够减少闪烁；它不是自动提高原图分辨率。二维像素 UI 是否需要 mipmap 与缩放策略有关，三维远处纹理通常更需要。开启后会增加存储与显存成本，应在目标画面中比较，而不是对所有素材一律开启或关闭。

压缩方式影响内存、质量、加载与平台兼容。无损适合要求清晰边缘的 UI，GPU 压缩适合更大的纹理预算，但格式与渲染器、设备能力相关。一个分辨率巨大的背景即使源文件压缩后很小，解码后的内存仍然可能很大；磁盘大小不等于显存占用。

## 12.4 不依赖外部图的纹理实验

以下完整脚本挂在独立 Sprite2D，生成一枚菱形纹理，适合观察 nearest 与 linear 的差异：

```gdscript
extends Sprite2D

func _ready() -> void:
	var image: Image = Image.create(32, 32, false, Image.FORMAT_RGBA8)
	image.fill(Color.TRANSPARENT)
	for y in range(32):
		for x in range(32):
			var distance: int = absi(x - 16) + absi(y - 16)
			if distance <= 12:
				var shade: Color = Color(1.0, 0.8, 0.2)
				if x < 16:
					shade = Color(1.0, 0.95, 0.5)
				image.set_pixel(x, y, shade)
	texture = ImageTexture.create_from_image(image)
	texture_filter = CanvasItem.TEXTURE_FILTER_NEAREST
	scale = Vector2(5.0, 5.0)
```

它是运行时生成资源，不产生导入缓存，不能用这个实验冒充 PNG 导入已验证。先观察五倍整数放大，再把比例改成非整数并移动节点，检查边缘是否稳定。之后可以由自己的绘图工具导出同尺寸图像，走一次真正导入流程，对比过滤、透明度和资源加载。

透明纹理边缘出现黑线时，检查原始透明像素颜色、图集边缘扩展和采样方式。不要仅在场景中缩小一像素来遮住问题。使用图集时还要确认区域边距与动画帧排列；错误区域裁剪可能把邻近帧的颜色采样进来。

## 12.5 字体与真实文字

界面字体不仅决定美感，还决定中文、标点、数字、混合脚本和用户输入能否显示。导入 TTF 或 OTF 后创建 FontFile 或相关字体资源，设入 Theme，再用真实最长文案测试。英文字体显示正常不代表中文覆盖完整，编辑器使用的系统字体也不代表发布包会包含同样字体。

中文字体通常体积较大，子集化可以降低体积，但需要明确动态内容范围。只保留当前按钮字符，可能让存档名、用户输入或后续关卡名称缺字。应保留可靠回退方案并测试缺字行为，同时核对字体许可是否允许嵌入与再分发。

多语言布局应测试更长文本、自动换行、按钮最小尺寸与焦点，不能只比较字体大小。毕业项目 HUD 使用英文提示，不宣称已经完成本地化。将文案移入翻译资源后，需要单独建立语言切换与长文本验证，资源导入正确只是第一步。

## 12.6 音频与模型导入

短音效与长音乐的解码、内存和循环需求不同。WAV、Ogg Vorbis、MP3 应依据质量和平台要求选择，导入后检查循环起止、单声道与立体声、首尾静音、峰值和实际听感。把文件扩展名改成 wav 不会完成格式转换；所有格式都应由有效源文件与正确解码器处理。

三维模型优先使用 glTF 2.0，常见载体是 glb 或 gltf 加外部资源。glb 方便集中交付，但仍需核对贴图、骨架、动画和材质。引擎能够直接处理 blend 的工作流依赖本机 Blender，不能把这种编辑器能力理解为发布玩家也必须安装 Blender。

模型实验先在 Blender 或其他工具建立一米立方体，应用合适变换，导出 glTF，再在 Advanced Import Settings 检查节点、网格、材质和动画。运行后确认尺寸、朝向、法线与碰撞一致。模型太小不要盲目把父节点缩放一百倍，先查清源单位和导出尺度。

Albedo 颜色通常按颜色空间处理，法线、粗糙度等数据纹理不能当普通颜色随意转换。法线方向错误会让凹凸反转，负缩放可能影响面朝向，透明材质可能增加排序问题。视觉异常应回到源与导入属性，不能靠添加很多灯光掩盖材质错误。

## 12.7 重导入与 UID

导入模型的场景由源数据产生，直接改生成结果可能在重导入时丢失。使用继承场景或外层包装场景添加脚本、碰撞和玩法节点，把自定义修改与美术源分开。更新模型后检查节点路径和动画名称，因为继承不能保证任意源结构变化都兼容。

Godot 4 的资源 UID 用于稳定识别资源；现行版本也会为脚本等文件生成相关 UID 辅助信息。UID 不是手工随便编的哈希，也不是文件绝对路径。让编辑器生成并维护，不要为了“修复路径”复制另一个资源的身份；重复身份会使定位不可靠。

动态加载若依赖字符串拼接，导出器不一定能像静态依赖那样识别全部资源。为关卡建立明确目录清单或资源索引，并测试导出包中的实际加载。原始 JSON 等非资源数据还要配置包含过滤器；编辑器能读到不表示导出包一定包含。

## 12.8 验证、排错与作业

正常验证是源文件修改后重导入生效、继承场景的玩法节点保留、移动素材后引用有效、目标平台画质与音频符合预期。异常验证覆盖缺少贴图、损坏文件、外部工具缺失、字体缺字、大小写路径差异和导出遗漏。以重新导入和实际运行验证，而不只浏览缓存。

作业是建立一套自创图像、短音效、字体和 glTF 模型资源清单。验收要求记录尺寸、导入参数、引用场景、许可与目标平台；新机器可从源重建；模型重导入不丢玩法；发布包可以找到所有动态资源。没有实际导出的平台必须保留未验证标记。
