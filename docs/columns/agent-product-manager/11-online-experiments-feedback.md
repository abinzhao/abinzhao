# 在线实验、反馈与因果：证明改善来自产品变化

## 学习目标

本章把“用户觉得更好”转换为可审阅的因果问题。学完应能选择随机化单位、预先定义分析口径、估算实验资源，识别分流异常与反馈偏差，并说明哪些证据只能支持观察性判断。

## 一、离线合格不等于在线有效

离线评测回答特定任务集上的行为是否符合契约；在线实验回答面对实际工作、学习成本和组织条件，产品变化是否改善结果。人工审阅更严、用户改变提问方式、工具排队和同事协作，都可能让线上表现不同。

上线前后比较还混合了季节、任务难度、人员熟练度和政策变化。改善不一定来自 Agent。随机分配在执行正确、样本足够且没有严重干扰时，可以帮助构建对照；它不是消除所有偏差的按钮。

[Microsoft Research 的在线实验检查清单](https://www.microsoft.com/en-us/research/publication/three-key-checklists-and-remedies-for-trustworthy-analysis-of-online-controlled-experiments-at-scale/)强调实验前、运行中与分析时的质量控制。这是公开研究实践，不是每个团队必须采用相同样本或阈值的行业标准。案例还需通过[离线任务评测](https://platform.openai.com/docs/guides/evaluation-best-practices)，才能申请在线测试。

## 二、先明确因果问题和随机化单位

教学问题是：“向合格专员提供带引用草稿，相对仅提供知识检索，是否提升工单任务的正确完成，而不增加错误采纳和敏感信息暴露？”比较的是整个产品能力，不只是底层模型。

按任务随机可以减少个体差异，但专员可能从实验组学习后在对照任务复用方法；按专员随机能稳定体验，却要处理同一专员多任务相关。若同事共享答案，可能需要按团队分配，代价是独立单位变少。按时间轮换还要考虑工作日、拥堵和学习残留，不能当作普通独立 A/B。

分析单位不必等于随机化单位，但方差计算必须尊重分配与聚类。一个专员处理一百张工单，不等于一百位独立用户。若无法避免交叉干扰，应先做受控可用性研究，或由统计协作者设计聚类、轮换等实验，而不是包装成干净的随机对照。

## 三、交付样例：预注册实验卡

以下为教学计划，招募、分流和测量均未执行。

| 字段 | 已填写样例 |
| --- | --- |
| 实验编号 | `EXP-LAB-READONLY-01`；首版没有写入能力 |
| 假设 | 带证据草稿提高正确完成；不是只提高草稿点击 |
| 合格人群 | 已授权服务台专员；任务属于允许政策问答类型 |
| 对照组 | 授权检索、证据列表和手动草稿编辑 |
| 实验组 | 同知识快照与权限，增加受限生成草稿 |
| 随机化 | 按专员稳定分配；团队共享污染列为设计风险 |
| 主指标 | 每位分配专员在固定窗口内正确完成的合格任务比例 |
| 质量判定 | 盲评抽样，按第十章量表核对来源与关键条件 |
| 护栏 | 错误采纳、敏感暴露、任务超时、人工复核负担 |
| 分析规则 | 预先定义专员权重、零任务处理、聚类与缺失口径 |
| 配置冻结 | 模型、提示、知识、工具、评分器与产品版本 |
| 扩量条件 | 业务有效性、区间和护栏共同评审，不按单一显著性 |
| 证据状态 | 基线、方差、样本量与运行窗口待授权测量 |

合格规则应尽量根据分配前可获得的信息确定。若实验影响任务创建量，事后只分析“实际使用过助手的人”，就会破坏原分配比较。主分析可采用按原分配的意向处理思路，使用者分析作为明确标注的辅助分析。

主指标还要说明估计什么：等权专员平均，代表典型专员；按任务加权，更接近典型任务，但高负荷专员贡献更大。不能在看到结果后切换到更有利的权重。任务完成率与总完成量应配套，避免通过减少接单使比例上升。

## 四、样本量是经营与统计共同决定的

最小可检测差异 MDE 是实验在给定错误率、功效和设计下希望识别的差异；最小业务有价值差异是值得支付成本的改善。二者相关但不相同。流量太低时只能检测巨大变化，不意味着微小变化没有价值。

纯计算练习：假定独立个体、两组等量、二项比例基线为 0.70、绝对差 0.05、双侧显著性水平 0.05、功效约 0.80。用简化正态规划近似：

```text
n_per_arm ≈ 2 × (1.96 + 0.84)² × 0.70 × 0.30 / 0.05²
          ≈ 1317.12，向上取整为每组 1318
```

**以上是教学假设下的规划计算，不是用户基线、模型结果或正式样本量结论。** 实际两比例公式、基线不确定性、失访、聚类和多重比较会改变需求。若采用专员内相关任务，不能把这里的独立个体数直接替换成工单数。

等规模聚类的简化设计效应 `1 + (m - 1) × ρ` 可以帮助理解：每簇大小 m 越大、簇内相关 ρ 越高，有效独立信息越少。真实簇大小不等、簇数量少时需更合适的方法。基线、方差和相关性没有数据时，交付范围估算及待测计划，不伪造精确样本。

窗口要覆盖工作节奏、任务到达和结果成熟，不能只追求凑够请求数。提前结束、延后转化和跨窗口恢复需预定义。样本要求超过可承受周期时，可以缩小问题、改做机制研究或承认暂时无法作强因果判断。

## 五、运行质量：先确认实验没有坏

SRM，即样本比例失配，检查实际分配是否与计划相容。分桶错误、某平台只上报实验组、资格过滤发生在分配后，都可能造成异常。但随机波动也会产生比例差，不能看到不是精确五五就认定故障。

运行检查至少区分分配、资格、曝光、任务开始和结果事件。分配正常而曝光异常，与分配本身异常是不同问题。按预定规则诊断分母、重复事件、时间、身份和客户端版本；不能删除看起来不平衡的人让比例恢复。

先运行 A/A 或影子分流可以检验管道，但 A/A 不证明业务有效，也不能覆盖之后代码引入的错误。实验过程中不要按候选表现持续调提示，否则评的是变化中的处理，版本与归因都会失真。

## 六、停止、护栏与多重比较

固定窗口实验不能每天按普通显著性检验“达到就停”；重复查看再择机结束会改变错误率。可采用预定终点，或由具备统计能力的协作者设计顺序检验与相应决策边界。仪表盘可以每天看安全和数据质量，但不能把监控偷换成无限次效果检验。

主指标、辅助指标、分层及探索性分析应预注册。测试多种模型、多种人群和大量指标，会增加偶然发现，需要适当多重比较控制或把结论标为待复验。探索可以产生假设，不能改写成事前预期。

安全停机不必等待效果统计显著。教学方案规定：出现确认的跨租户泄露或未授权写入，立即停止相关能力并调查。零事故样本不证明绝对安全；对低概率高影响风险还要依靠权限控制和对抗验收。

## 七、反馈和观察研究的正确用途

点赞受礼貌、界面位置和用户自选影响；沉默可能代表满意，也可能代表放弃。反馈适合发现原因、提出假设与挑选人工复核任务，不应直接当成全部任务的客观成功率。

教学反馈表包括任务编号、使用阶段、问题类型、是否采用、证据位置、严重度与回访授权。原话仅在取得授权后记录，安全内容进入受限处理，不进入通用分析看板。不能为了回访强制收集多余个人信息。

没有随机实验时，可以报告趋势、分层观察或用户研究，但要列出替代解释。倾向评分等方法也依赖可观测混杂和建模假设，不能用一个分析方法名称把观察结果升级为确定因果。

## 八、失败案例、工作坊与完成标准

**失败案例：只看使用者。** 高水平专员更愿尝试助手，使用者结果更好，却不能证明提供能力让全部专员改善。纠偏是保留原分配分析，并单列选择机制。

**失败案例：周五显著就停。** 团队持续查看多个指标，挑最好的一天报成功。纠偏是事先确定终点、主指标和分析方案，探索结果另行复验。

工作坊要求交付实验卡、随机化与分析单位说明、样本规划、质量检查和停止决策。用“同事共享草稿、实验组漏事件、零任务专员、超时结果晚到”四种教学场景走查，说明每种是否破坏因果或口径。

完成标准是另一名协作者能在不看结果的情况下执行规则，并区分业务价值、统计不确定性和安全决策。文档验收可检查口径一致和公式可复算；真实因果结果只能来自授权且设计有效的实际实验，本章没有该证据。
