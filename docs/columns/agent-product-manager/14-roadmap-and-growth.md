# 路线图、实验与增长：让扩量建立在任务价值上

## 学习目标

本章把路线图从功能日历变成假设、依赖和放行条件。学完应能设计不同成熟度的实验，判断激活和留存口径，制定不激励过度自动化的收费与扩量规则，并保留停止产品的选择。

## 一、路线图不是先答应更强自治

任务价值、技术可行、安全控制和经济持续性是不同不确定性。先承诺某月上线多 Agent 或全自动工单，容易把组织推向“为了赶日期跳过验证”。路线图应先说明要降低什么不确定性，再说明功能和时间假设。

可以同时开展用户研究、文档规格和技术验证，但存在真实依赖：没有知识责任人，无法长期保证政策有效；没有可信批准与恢复机制，不能开放写入；没有分母可靠的事件，不能解释增长实验。

[GitLab 公开 PM 岗位实践](https://handbook.gitlab.com/job-families/product/product-manager/)体现结果、决策与协作责任，但不代表行业统一岗位模板。[Anthropic 的 Agent 模式文章](https://www.anthropic.com/engineering/building-effective-agents)强调复杂度取舍；因此路线图不应把更多 Agent、更多工具或更长自主运行当成自然进步。

## 二、交付样例：有证据阶段门的路线图

以下为教学方案，不代表任何阶段已达成，也不是固定交付周期承诺。

| 阶段与问题 | 工作与依赖 | 放行证据 | 暂停或退出 |
| --- | --- | --- | --- |
| 发现：任务值得做吗 | 授权观察、替代方案、任务与价值卡 | 目标任务、频率和失败成本有可核验依据 | 需求罕见或现有检索已足够 |
| 只读：能正确给草稿吗 | 知识治理、权限、PRD、风险任务集 | 任务量表、正常与拒绝路径实际验收 | 来源不可靠或权限边界不成立 |
| 试点：真实工作有价值吗 | 有效分流、最小日志、人工复核与支持 | 效果与区间、护栏、使用研究和成本账 | 错误采纳、过重复核或无业务价值 |
| 受限写入：能控制副作用吗 | 精确批准、幂等、回读、恢复与演练 | 禁止字段、状态未知等边界用例通过 | 业务服务不支持安全恢复 |
| 扩量：能持续经营吗 | 容量、值班、合同、费用与撤销能力 | 运行指标、责任人、预算和回退证据 | 维护不可持续或残余风险不可接受 |

各阶段应有负责人、下一次评审、证据位置和阻塞项。条件不满足时，可以退回前阶段，不用“完成了界面”替代放行证据。真实效果门槛由业务和风险共同设定，本表没有通用成功率。

日期可以用于协调，但要区分承诺与预测。外部知识、采购、法务或服务权限阻塞时更新依赖与范围，不通过隐藏风险维持原日历。对外承诺只包括已确认可交付能力，实验能力明确状态。

## 三、机会排序需要解释，不需要虚假精确

任务量、单任务价值、证据可信度、建设和运维成本、风险、依赖，可以作为排序维度。评分用于组织讨论，不是客观真值。把未知数据填成中位数，得到小数排名，会产生不应有的确定感。

教学机会记录如下：

| 机会 | 价值与证据状态 | 风险与依赖 | 教学决策 |
| --- | --- | --- | --- |
| 带引用答复草稿 | 减少查找与整理；真实节省未测 | 授权知识与复核 | 先验证 |
| 工单分类建议 | 可能减少重复填写；频率未测 | 标签定义与权限 | 可列后续候选，不先写入 |
| 自动外发答复 | 减少点击但影响外部对象 | 不可逆传播与批准 | 不在案例范围 |
| 自动退款 | 涉及资金与业务裁量 | 高影响、未知恢复 | 明确排除 |

排序同时记录反证：如果专员只花很少时间整理，生成草稿价值会下降；如果知识权限混乱，优先治理知识可能比新增模型更有价值。一次评审后保留决策依据，而不是不断修改历史分数使其吻合最新方向。

## 四、激活应代表首次价值，而非首次调用

注册、下载模型、发一条消息都不是任务完成。教学激活定义为：合格专员首次完成允许任务，能查看证据并编辑草稿，且关键质量检查通过。产品事件可记录流程完成，质量事实仍需独立抽样或适合的检查，两者不能混为一项即时事件。

首次体验应展示允许范围、数据去向、证据和人工路径。权限未准备好时解释如何获取授权，不提供绕开权限的演示捷径。高风险业务的“快上手”不应隐藏限制；下载本地模型等有成本的操作应明确征求同意。

漏斗可拆为具备机会、进入入口、理解范围、完成配置、开始任务、获得合格草稿和结束任务。各阶段退出原因不同：没有任务、没有权限、模型慢、内容不可信、不了解编辑方式。降低退出必须针对原因，不能都归结为按钮不够明显。

## 五、留存要考虑任务机会和组织变化

低频政策问答可能一个月只发生几次。用户没回来不一定是不满意，可能没有新任务；高频登录也可能只是反复纠错。应按首次激活队列观察，在明确窗口和合格机会口径下报告重复完成。

教学口径同时报告“全部激活用户回访”和“有后续合格任务机会用户的再次完成”。后者能帮助解释任务频率，但机会识别本身不能依赖实验组是否使用 Agent，否则产生选择偏差。两者分母与缺失需并列。

团队迁移、知识范围变化和岗位调整也会影响留存。增长看板要按产品与知识版本分层，避免把不同能力的用户混在一起。增加提醒需要用户偏好与授权，不以不断打扰或制造紧迫感提高活跃。

## 六、交付样例：增长实验卡

以下是未执行教学设计，沿用第十一章的因果与质量要求。

| 字段 | 已填写样例 |
| --- | --- |
| 观察问题 | 假设用户在看到证据前误以为答案不可核验，尚无真实研究证据 |
| 候选变化 | 在草稿旁展示证据摘要和适用条件，保留详细来源入口 |
| 对照 | 相同证据在可展开区域，不改变知识、模型与权限 |
| 假设 | 更易理解证据，从而提高合格任务完成，而非仅增加点击 |
| 主分析 | 按原随机分配比较；样本和窗口由基线规划 |
| 护栏 | 错误采纳、阅读负担、延迟、辅助技术可访问性 |
| 不允许 | 隐藏警告、默认自动采用、弱化拒绝或收集多余个人信息 |
| 停止与决策 | 边界事故停能力；效果不确定则保留缺口，不宣布增长 |

研究阶段可以先做可用性走查，确认用户理解证据和适用条件；它回答机制问题，不替代大规模效果证据。实验组只改变目标界面因素，否则同时换模型就难以识别是哪项变化有效。

定性反馈与定量结果互补。点击提高而正确完成不变，可能只是信息更显眼；完成提高但检查负担显著增加，需要按全成本重新判断。不要挑最好的一项指标改写原假设。

## 七、定价、包装和增长激励

按席位、任务量、套餐或 BYOK 收平台能力费都有取舍。席位便于预算但低频用户可能觉得浪费；按任务需要清楚计量与失败处理；按结果收费要解决结果判定、归因和争议。不存在适合所有 Agent 的唯一模式。

教学包装建议是先保留透明限额的只读试点，付费范围只包含已验证能力，不把未验证写入作为销售承诺。明示任务额度、可计费事件、失败重试、退款或争议处理、日志保留与退出导出；具体价格待真实成本和支付意愿研究。

结果收费不能把“用户点击采用”自动当作业务成功，也不能为提高计费而隐藏失败。平台代付和 BYOK 的费用来源应分别说明，避免用户承担两次模型费用而不知情。本地处理也有设备和支持成本，不可宣传成无成本。

增长激励要与安全边界一致。销售不应承诺自动退款，设计不应取消关键批准，工程不应为了活跃增加无意义循环。续费与扩量依据持续价值、稳定运行和预算，不能仅凭首次演示惊艳。

## 八、失败案例、工作坊与完成标准

**失败案例：工具数当路线图成果。** 每月新增连接，知识和权限问题积累。纠偏是以可完成任务和维护责任验收，不以能力清单扩张验收。

**失败案例：活跃上升源自返工。** 用户反复重跑错误草稿，调用数上涨却工作更慢。纠偏是将重复、返工和正确终态纳入任务漏斗。

**失败案例：没有再次任务就判流失。** 低频用户被营销打扰。纠偏是保留任务机会分母、主动偏好和真实研究。

工作坊交付阶段门路线图、机会排序、激活与留存定义、增长实验卡和定价说明。走查“知识负责人缺席、客户要求退款工具、指标上涨但复核增加、模型停止供应”四种情形，给出继续、缩范围、回退或退出的理由。

完成标准是每项路线图工作对应不确定性与证据，扩量不突破权限，增长不牺牲质量。业务增长、支付意愿和续费都需要真实研究与测量；本章只完成设计，不提供已验证商业成功。
