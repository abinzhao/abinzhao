# 价值主张与产品定位：让假设可以被推翻

## 学习目标

本章将任务研究转成可决策的产品策略。学完应能解释用户、付款者和风险承担者之间的差异，比较真实替代方案，写出可证伪的价值假设，并决定最先验证哪个不确定条件。没有市场数据时，不得推导市场规模或确定收益。

## 一、用户价值不是功能数量

“接入模型、支持检索、支持工具”描述实现能力，没有说明用户为什么换工作方式。价值应落在任务结果，例如更容易找到有效政策、减少遗漏条件、缩短可接受答复的主动处理时间。价值还可能是控制：用户知道系统没有越权，能查看证据并在失败时继续工作。

必须识别价值链中的不同角色。使用者可能希望减少操作，业务负责人更关心稳定性，采购者关心合同和全成本，安全与法务负责判断边界。只满足使用者，不一定能进入组织；只满足采购，不一定获得持续使用。策略要同时说明谁受益、谁承担风险、谁批准、谁支付。

[GitLab 的岗位手册](https://handbook.gitlab.com/job-families/product/product-manager/)提供产品方向与跨职能决策的公开实践。[OpenAI 的评测建议](https://platform.openai.com/docs/guides/evaluation-best-practices)强调针对任务定义测试，支持将价值承诺落实为可测结果，但并不证明某个产品一定有需求。本章的定位方法是产品分析建议，不是这两项来源的统一公式。

## 二、替代方案决定增量价值

竞争不只是其他 Agent。用户可能使用站内搜索、收藏夹、规则表、同事咨询或已有自动化。新产品需要比较“完整任务成本”，而不是模型输出速度与手动输入速度。草稿很快但复核很慢，可能没有正收益；证据可靠但导入成本过高，可能无法被采用。

替代方案分析至少包括效果、控制、切换和维护。效果是任务结果能否达标；控制是错误可发现、可暂停、可恢复；切换包括培训、工作入口、数据迁移；维护包括知识更新、权限管理和运行值守。一个便宜的搜索改进可能比动态 Agent 更适合首版。

| 替代方案 | 可能优势 | 需要验证的限制 |
| --- | --- | --- |
| 手动知识搜索 | 不引入生成失真，工作习惯稳定 | 查找与版本核对负担是否显著 |
| 搜索加规则提示 | 可预测、较容易维护 | 能否覆盖复杂咨询与语言变化 |
| 固定检索生成 | 可整理草稿且保留控制 | 证据支撑、复核负担与拒答质量 |
| 受限 Agent | 有机会处理澄清与有限探索 | 是否真正增加完成率、成本是否可控 |
| 人工专家接管 | 能处理例外与解释冲突 | 等待与资源瓶颈，是否可持续 |

这是一张待验证比较表，不能自行填入“显著提升”或具体百分比。实际项目应给每个判断添加证据编号和环境范围。

## 三、交付样例：产品策略一页纸

“澄明服务台”以下定位全部是教学假设，尚未确认用户需求和商业可行性。

| 字段 | 已填写样例 |
| --- | --- |
| 首批对象 | 经批准的 `tenant-lab` 内部服务台专员 |
| 核心任务 | 找到有效政策，形成带依据、可编辑的内部答复草稿 |
| 待验证问题 | 查找、版本判断和条件核对可能形成重复劳动 |
| 价值主张 | 在不扩大权限的前提下辅助查证与起草，保留专员最终判断 |
| 差异化方向 | 证据版本、范围过滤、拒答与人工接管，而非“万能助手” |
| 首版入口 | 从当前工单显式启动；不得后台自动读取所有工单 |
| 非目标 | 自动退款、自动外发、全组织搜索、替代业务审批 |
| 当前替代 | 手工知识搜索与专家咨询，实际使用比例待研究 |
| 经营假设 | 任务收益覆盖复核、推理、知识治理和运维总成本 |
| 失败退出 | 无稳定证据来源、复核负担不降或控制不足则缩小范围 |
| 证据状态 | 仅形成策略规格，研究、模型评测和收入均未验证 |

这张一页纸有意让定位窄于技术能力。可以调用外部网页，不意味着应该开放网页；能够写工单，不意味着写入是首批用户的核心价值。范围越清楚，越能形成有意义的对照评测和上线门槛。

## 四、将愿望写成可证伪假设

有效假设包含对象、条件、预期变化、测量方法和推翻条件。例如：“在已批准知识覆盖的咨询任务中，固定检索生成可能降低达到草稿验收标准的主动处理时间；若加入复核和修正后不低于手动基线，时间价值假设不成立。”这里没有预填改善比例，阈值应由实际业务价值和实验设计确定。

不要把所有失败都解释为“用户还没学会”。如果任务目标选错、知识无法治理、用户不愿承担复核责任，继续培训未必有用。先划分假设：需求、可行性、采用、经济性和安全。需求成立不意味着模型能完成；模型能完成不意味着有人愿意使用；有人使用不意味着收入覆盖成本。

### 已填写的假设与验证表

| 假设 | 验证方式 | 推翻或暂停条件 |
| --- | --- | --- |
| 查证是重要负担 | 授权观察与时间研究，覆盖反例 | 主要瓶颈实际上是等待审批 |
| 有效知识可覆盖任务 | 按任务逐条检查证据与适用版本 | 大量任务需要未记录的专家经验 |
| 草稿值得使用 | 盲评可用性与真实编辑行为 | 用户重写全部内容或难以核对证据 |
| 可受控运行 | 权限、拒答、取消和恢复走查 | 单次越权可绕过应用校验 |
| 可经营 | 按任务全成本敏感性测算 | 保守条件下预算无法承担 |

验证顺序不必追求华丽原型。先检查阻断性条件，如知识授权和真实任务价值；再用低成本规格或人工辅助流程验证交互；有必要才投入模型评测和运行系统。人工辅助实验也要告知参与者并取得授权，不能伪装成自动完成。

## 五、机会排序与证据折扣

常见优先级表将影响、覆盖和信心相乘，再除开发成本。公式可以帮助讨论，但分数不是事实。若输入都是猜测，排序精确到小数只会制造确定性。更实用的是记录证据强弱、可逆性、阻断依赖和失败代价，给机会分组，而不是依赖单一总分。

教学案例先排序为：有效知识回答契约、草稿与证据体验、授权只读接入、受限探索、审批写入。理由是后面的能力依赖前面的控制和证据。若研究显示主要任务是结构化字段校验，顺序应改变，甚至取消 Agent 方向。路线图要能被证据改变，否则价值验证只是装饰。

对不确定机会，可以建立“获得信息的价值”判断。一个小实验若能决定是否投入大量工程，比一个提升观感但不改变决策的演示更值得优先。但研究也有成本和风险：没有明确决策用途时，不应无限收集用户资料。

## 六、失败案例与验收

**失败案例：把总任务量当可服务市场。** 团队把全部工单乘单价，忽略知识覆盖、用户授权、处理类型和采用率。纠偏是从允许服务的任务集合出发，逐层记录覆盖、采用、完成与付款限制；缺数字就保留缺口。

**失败案例：所有失败都加功能。** 用户不信任答案，团队新增记忆、多 Agent 和自动写入。实际问题是引用无法定位到有效条款。纠偏是先回到价值链，修复证据检查，而非扩展行为范围。

验收策略时，请读者回答：服务谁，解决什么，为什么胜过当前替代，哪些证据会推翻方向，不能做什么。如果只能找到功能列表，策略尚未完成。再选一个重要假设检查测试能否出现“不成立”的结论；若无法失败，就不是验证。

## 七、工作坊

1. 完成一页纸策略，将所有未确认信息标为假设。
2. 找三个非 AI 替代方案，比较完整任务而非局部动作。
3. 写五条可证伪假设，指定证据和推翻条件。
4. 按阻断依赖安排验证顺序，说明为什么暂不开放写入。
5. 模拟一条反证：用户主要瓶颈是审批等待，重新做机会排序。

## 完成标准

交付策略一页纸、替代方案表、假设账本与验证顺序。至少有一条可导致取消或缩小产品方向的反证；用户、批准者、付款者和风险承担者被分别识别。任何收益数字必须有合法数据来源，教学假设不能成为市场结论。
