# 工具、MCP 与记忆：连接能力不等于行动授权

## 学习目标

本章把模型可用能力转成业务契约。学完应能写出工具卡，解释 MCP 的连接角色及信任边界，区分会话、任务状态、长期记忆与知识，并定义信息撤销后哪些地方必须停止使用。接口字段正确不代表动作安全。

## 一、工具调用是受控执行链

[OpenAI 工具调用文档](https://platform.openai.com/docs/guides/function-calling)说明，模型提出工具调用，应用执行工具，并向模型提供结果。模型不应自行取得当前用户的权限，也不能凭输出中的“已成功”证明动作发生。执行器需要校验身份、范围、参数、资源状态和批准条件，再记录实际结果。

工具 Schema 描述字段与类型，解决“如何表达请求”；业务授权解决“谁在什么条件下可以执行”。即使结构化输出完全符合 Schema，工单也可能属于其他租户、字段不在白名单、审批已过期。授权信息必须来自可信会话与服务端规则，而非模型生成参数。

只读工具也有风险：可能返回敏感材料、暴露未授权资源存在、消耗大量预算或把外部内容中的指令送入上下文。工具卡既要写副作用，也要写读取范围、输出最小化、错误语义与数据去向。

## 二、MCP 提供连接契约，不代替业务治理

核验时，[MCP `2026-07-28` 规范](https://modelcontextprotocol.io/specification/2026-07-28)是 `latest` 指向的修订。课程采用该具体版本，不假定所有客户端已支持其全部能力。实施前应确认目标 Host、Client、Server、传输方式和能力协商，不直接复制旧修订例子。

Host 承载面向用户的应用与控制，Client 负责与 Server 的协议交互，Server 提供可用能力。Tools、Resources、Prompts 是规范中的不同原语；它们描述接口形态，不意味着返回内容可信。工具描述、注释、资源和提示模板都应按来源进行信任判断，不能因为“通过 MCP 返回”就升级成最高优先级指令。

授权还涉及服务边界。[MCP 授权安全考虑](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/security-considerations)讨论受众校验、混淆代理及令牌转交问题。不要把上游令牌不经校验地透传给下游服务；具体要求需结合传输及授权架构。连接成功只能证明通信路径的一部分，不证明用户已批准读写，更不证明第三方数据处理满足合同要求。

## 三、交付样例：工具卡

以下是应用层教学契约，不是可直接运行的 MCP 协议报文。

| 字段 | 只读工具 `search_authorized_kb` |
| --- | --- |
| 用途 | 查找当前用户可读取的有效知识段落 |
| 输入 | 问题文本、问题类别、发生时间；长度与格式由应用校验 |
| 可信上下文 | 已验证用户、`tenant-lab`、角色、任务标识，由执行器注入 |
| 模型不可控制 | 租户、权限范围、凭据、数据出口和来源批准状态 |
| 输出 | 授权段落、版本、有效期、定位、覆盖不足说明 |
| 副作用 | 只读，但会产生受控审计记录和资源消耗 |
| 数据最小化 | 不返回未授权标题，不返回完整工单，不包含凭据 |
| 错误 | 无证据、权限不足、暂时故障、预算耗尽，分别编码 |
| 重试 | 暂时故障在预算内可重试；权限失败不可扩大范围重试 |
| 验收 | 跨租户请求被拒绝；过期来源不作为有效证据；结果可定位 |

写入工具应另建卡片，而不是给同一搜索工具加任意操作参数。教学 `propose_ticket_patch` 只生成建议；真正 `apply_approved_ticket_patch` 还需要字段白名单、资源版本、精确审批与幂等标识。第八章将展开未知结果与恢复，这里先要求两个动作不能在产品语义上混淆。

```json
{
  "tool": "propose_ticket_patch",
  "task_id": "TASK-LAB-01",
  "ticket_id": "TICKET-LAB-001",
  "expected_version": "rev-7",
  "patch": { "category": "policy-question" },
  "evidence_refs": ["KB-LAB-001:v3:paragraph-2"],
  "status": "proposal_only"
}
```

上述标识、字段和版本均为教学假设。该对象没有批准凭据，不能拿到执行器后直接写入。

## 四、记忆是生命周期问题

会话历史保存交流内容，任务状态保存本次工作进度，长期记忆保存跨会话可重用信息，知识保存经批准的业务事实。这些对象的来源、有效性、访问范围和删除方式不同。把聊天历史全部保留并塞进提示词，不等于设计了可靠记忆。

偏好可以影响表达风格，不得产生权限。例如“用户喜欢自动完成”不能成为免审批依据；用户曾说“我有管理员权限”也不能覆盖当前身份系统。记忆读取后仍需校验适用租户、当前权限与有效期。工具返回的恶意指令不能被写成“用户长期偏好”。

[Anthropic 上下文工程实践](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)涉及摘要与记忆以管理有限上下文，但没有承诺摘要不会遗漏。摘要需要保留来源、限制条件和尚未完成的动作；对于实际写入状态，可信事件记录比模型摘要更可靠。

## 五、交付样例：记忆规格

| 字段 | 已填写样例 |
| --- | --- |
| 候选记忆 | “草稿默认使用简明中文”，明确属于表达偏好 |
| 产生方式 | 用户显式选择保存；不能因一次聊天自动永久记住 |
| 作用范围 | 当前用户与 `tenant-lab`，跨租户不复用 |
| 存储对象 | 偏好值、来源方式、创建时间、有效状态、删除标识 |
| 不保存 | 完整工单、账户、凭据、模型猜测的身份、未经批准政策 |
| 读取约束 | 每次确认仍有效且当前用户匹配；不改变工具权限 |
| 更新与撤销 | 用户可编辑、关闭和删除；旧值立即停止参与新任务 |
| 派生对象 | 摘要、缓存与索引如包含该信息，纳入删除传播清单 |
| 审计例外 | 必要记录与删除要求存在冲突时由治理角色判断并说明 |
| 当前状态 | 只有规格，未实现存储与删除，不能宣称本地或完整可删除 |

记忆不是模型训练。删除应用记忆，也不等于能从已训练权重移除信息；反过来，使用不训练政策也不代表没有会话保存。产品需要分别说明数据传输、日志、应用状态和训练用途，第十二章将进一步讨论部署与隐私。

## 六、失败案例与验收

**失败案例：把工具描述当批准。** 一个第三方工具自称“只读且安全”，实际将问题发送外部系统。纠偏是查清执行行为、网络出口、权限和合同，不仅看工具名称或注释。无法检查来源时缩小接入范围。

**失败案例：长期记忆保存过期权限。** 用户以前可看某项目，离组后记忆仍推荐并读取该项目。纠偏是权限每次以可信系统校验，记忆仅提供候选上下文；撤销后清理派生缓存。

**失败案例：摘要把建议写成完成。** 上轮提出工单修改，摘要写为“工单已更新”，恢复后跳过执行。纠偏是状态来自事件与回读，不以摘要判断动作完成。

验收时检查从模型建议到工具执行的每个信任转换点；分别测试结构正确但越权、工具暂时失败、来源带恶意指令、记忆撤销、跨用户读取和摘要错误。只读与写入应有独立用例，连接通畅不能替代行为验收。

## 七、工作坊

1. 填一张只读工具卡和一张受控写入卡，明确可信字段的来源。
2. 画 Host、Client、Server 与实际业务系统的数据流，注明协议修订。
3. 为一个偏好设计保存、读取、更新、撤销及删除传播。
4. 植入三类教学恶意材料：越权指令、伪工具安全说明和伪权限记忆。
5. 走查所有动作是否仍经过应用校验，记录未实现控制。

## 完成标准

交付工具卡、连接信任图和记忆规格。能够区分 Schema、协议、授权和执行；没有模型生成字段可以直接覆盖身份、租户或批准信息。删除与撤销具有明确对象和传播边界，未实现部分标注待验证。
