# 成本、延迟、选型与隐私：设计可持续的任务经济

## 学习目标

本章要求产品经理同时回答“谁付费、为何值得、最长等待多久、数据去了哪里”。学完应能构造全成本账、解释预算与效果的冲突，建立模型候选决策，并避免把自带密钥或不用于训练误认为数据不离端。

## 一、经济单位应是任务，不是一次模型调用

Agent 可能多次检索、生成、校验和重试。单次请求便宜，不代表完成任务便宜。应统计任务总调用成本、成功任务分摊成本和全流程人力，并分别报告失败、拒绝与未知结果。

模型成本可按实际计费输入、缓存输入、输出等类别乘当期价格核算；工具、搜索、存储、网络和执行环境可能独立收费。推理相关 token、批量、缓存和计费粒度由供应商契约决定，不能仅用界面显示的回答字数估算账单。

`每成功任务推理成本 = 全部相关任务推理支出 / 成功任务数` 能揭示失败重试的代价，但还不是全成本。人工检查、事故处理、知识维护、隐私治理和固定建设费用都要单列。正确拒绝是否属于成功由任务契约决定，不能为了成本好看改变分类。

价值可以是时间释放、质量降低损失、缩短周期或改善可及性，但不能重复计价。时间释放只有在确实减少支出或转化为额外有效产出时，才能进一步宣称现金收益；容量价值不是自动发生的收入。

## 二、交付样例：商业假设和敏感性账

**以下数字完全是教学预算假设，人民币仅作计价单位，不是供应商价格、员工工资或业务测量。** 假定每月一千个合格任务，人工流程平均八分钟，助手流程平均六分钟，后者已包括检查、失败回退与后续返工。教学人力计价为每小时六十元。

| 项目 | 教学假设及算法 | 月度金额 |
| --- | --- | --- |
| 释放容量价值 | `1000 × (8 - 6) / 60 × 60` | 2000 元 |
| 可变技术成本 | 模型、工具、运行合计每任务 0.60 元 | 600 元 |
| 固定增量成本 | 维护、评测与治理的教学月度分摊 | 800 元 |
| 总增量成本 | `600 + 800` | 1400 元 |
| 净容量价值 | `2000 - 1400` | 600 元 |
| 教学 ROI | `600 / 1400` | 约 42.9% |

公式只在假设成立时成立。建设投入和严重事故损失未获得估计，应标待测，不以零代替。评审时还应核对固定分摊是否含建设摊销、管理时间和合规成本；真实决策需纳入完整现金流与时间范围。

保持每任务节省两元、技术成本零点六元、固定成本八百元时，盈亏平衡量为 `800 / (2 - 0.60)`，约五百七十二个任务。若只节省半分钟，每任务价值为零点五元，低于可变成本；增加规模不能扭转负贡献，还会扩大损失。

因此不能只给一个乐观 ROI。应分别改变任务量、成功率、复核时间、失败返工和技术成本。对未测变量列范围及取证方式，例如观察授权专员的完整任务耗时，而不是只记录模型运行时间。安全与合法性是门槛，不得通过“泄露损失乘低概率”来批准本不允许的行为。

## 三、预算也是产品行为契约

预算至少包括单任务费用、调用次数、执行时长、上下文、并行数和租户周期额度。长任务若只受 token 上限控制，仍可能因工具循环消耗大量外部资源。限制必须在可信执行层强制实施，不能仅在提示中要求节约。

| 字段 | 已填写教学规格 |
| --- | --- |
| 任务类型 | 只读政策答复草稿；写操作不因预算剩余自动获得许可 |
| 探索限制 | 最多两轮检索，之后转澄清或人工处理 |
| 费用限制 | 应用维护任务预算，含模型与可计量工具支出 |
| 时间限制 | 到达配置的任务截止时间，停止后续调用并说明未完成 |
| 超预算说明 | 已有证据、未完成检查、可编辑草稿和人工入口 |
| 并发限制 | 每租户与全局都有上限，避免一人占满队列 |
| 核算差异 | 预估与实际账单对账；工具费用未知不默认为免费 |
| 异常策略 | 不静默降低权限、删证据或无限重试来满足预算 |

预算用尽不等于任务成功。可以输出明确标为未完成的证据摘要，也可以拒绝生成高风险草稿；选择依据是任务契约。成本优化后的新路径必须重新评测，不能假定更短回答不会丢失条件。

## 四、延迟由整条关键路径决定

[OpenAI 延迟优化文档](https://platform.openai.com/docs/guides/latency-optimization)讨论减少生成、减少请求、合理并行与不使用模型的替代路径。具体优化比例依环境而变，本课程不采用其演示数字作承诺。

用户等待时间包括排队、检索、模型、工具、校验和界面呈现。首 token 很快但最终结果很慢，只改善了局部体验。应分别量测首反馈、可用草稿、任务终态及 P50、P95 等分位；不能把各阶段 P95 相加当作总 P95。

无依赖且已授权的检索可以并行；依赖上一步结果的动作不能抢先执行。写入即使并行更快，也必须满足批准和版本条件。缓存要包含租户、权限、知识版本等边界，权限撤销后旧缓存不能继续泄露内容。

减少长上下文与无意义轮次通常值得试验，但摘要可能遗漏约束，短模型路径可能降低质量。优化报告应配套任务效果、护栏与成本，不仅呈现延迟。流式界面还要说明正在形成草稿，不让暂未核对的内容被误认为最终结论。

## 五、模型选型先过门槛，再比较效用

候选不能只按公开榜单排名。任务语言、证据引用、工具参数、拒绝、延迟、区域、数据政策、可靠供应与授权环境，都会影响产品。上下文长度是容量，不等于有效利用全部内容的能力。

教学决策卡不固定模型名和最新价格，实施时填入实际可访问候选、日期、版本和合同证据：

| 决策字段 | 已填写方法与门槛 |
| --- | --- |
| 数据与地区 | 先确认可传字段、区域和保留；不合格候选直接排除 |
| 行为能力 | 用同一任务集测试证据、澄清、参数与拒绝，不靠宣传 |
| 运行表现 | 在目标并发量测端到端延迟、限流和错误恢复 |
| 成本口径 | 任务总成本，保留失败与复核支出 |
| 供应策略 | 记录版本生命周期、额度、维护通知与替换路径 |
| 决策状态 | 无真实运行数据，暂不指定胜出模型 |

路由可将明确任务交给固定检索或规则，复杂任务再交较强候选；但分类器会误路由，也需要验收。回退候选必须满足同样的数据、授权和安全门槛，不能因主模型超时就把数据发给未批准供应商。模型、提示、路由和知识同时变化时，很难归因，应记录版本并控制变化。

## 六、BYOK、云端与本地是不同边界

BYOK 指用户提供自己的 API 密钥，可能降低平台代付成本并增加选择权，但通常仍把请求发给模型服务。它不能证明离线、本地、零保留或隐私合规。密钥泄露、额度误用和供应商账号策略也成为产品责任。

[OpenAI 数据控制文档](https://platform.openai.com/docs/guides/your-data)区分训练使用、滥用监测日志和应用状态。API 默认不用于训练不等于不传输或不保留；零数据保留等安排有资格、批准、端点和功能限制，第三方工具或 MCP 服务要另行核对。

| 模式 | 数据去向 | 产品需要告知的限制 |
| --- | --- | --- |
| 平台管理云密钥 | 产品与批准供应商按架构接收数据 | 传输、存储、地区、工具方与合同 |
| 用户 BYOK 云调用 | 用户账号对应的云模型，可能仍经过产品代理 | 账单、密钥保存、代理可见性与供应商政策 |
| 本地模型 | 按设计在设备或内网执行 | 遥测、更新、工具外联和同步仍可能出网 |

真正本地处理还要检查模型文件获取、日志、崩溃上报、知识索引、浏览器缓存、备份与工具调用。公开模型资源可以在用户明确操作后下载，但不等于其后所有链路离线。设备内存、启动时间、耗电、量化质量和兼容性需在目标设备实测；没有测量不能保证体验。

教学案例默认最小数据，不在任何日志、对话或作品集中放密钥。BYOK 的保存、可撤销性、清除和错误提示需写明确规格；密钥不能进入模型提示。示例只使用“用户密钥待安全注入”，不展示真实值。

## 七、失败案例、验收与工作坊

**失败案例：便宜模型增加复核。** 调用费用下降，错误草稿导致检查时间与返工上升。纠偏是比较每任务全成本与质量，不只比 token 单价。

**失败案例：本地界面调用云模型。** 产品宣传“数据不离端”，实际请求和分析日志出网。纠偏是按数据流逐项核验，文案严格匹配架构和运行证据。

工作坊交付商业假设账、三种敏感性场景、预算规格、延迟分解和模型决策卡。用预算耗尽、限流、主模型故障、权限撤销后的缓存和 BYOK 撤销走查，检查回退没有突破既有边界。

完成标准是数字可复算、未知成本不当零、容量与现金收益分开，所有候选通过数据门槛后才比较。文档检查不能证明真实成本、设备表现或隐私隔离；这些需要授权账单、端到端运行及网络与存储核验，本章未执行。
