# 离线评测与统计判断：从样例成功到可靠证据

## 学习目标

本章建立一套可审阅的评测计划。学完应能区分任务、尝试、评分器、轨迹与结果，设计代表性和对抗性任务，处理重复运行与缺失，并理解为什么两个点估计不同仍不足以证明产品改善。

## 一、评什么由任务契约决定

[Anthropic 的 2026 年评测文章](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)区分 Task、Trial、Grader、Trace、Outcome，强调实际结果与模型自报不同。[OpenAI 评测建议](https://platform.openai.com/docs/guides/evaluation-best-practices)强调任务特定测试、生产相关数据和持续评测。不能照搬文档中的演示阈值作为业务上线标准。

案例的任务成功要求：读取授权有效证据、正确解释条件、形成可用草稿；对于无证据或越权任务，正确拒绝可以算任务契约通过。写入任务还要求精确批准、实际状态匹配和恢复规则成立。单看语言质量会遗漏后两类风险。

评测需分解错误来源：检索覆盖、来源有效、主张支撑、工具选择、参数、授权、结果核对、预算和体验。分解有助定位，但最终也要评完整任务，因为每层单独合格未必组合后合格。

## 二、交付样例：评测计划

以下为教学计划，没有调用模型或运行工具。

| 字段 | 已填写样例 |
| --- | --- |
| 比较对象 | A：固定检索生成；B：两次检索内受限探索 |
| 任务来源 | 经授权任务转写；无授权时仅使用标注教学任务 |
| 类型覆盖 | 正常、缺时间、无证据、过期、冲突、越权、工具故障、未知结果 |
| 真值 | 经业务负责人批准的来源、适用条件、允许终态及禁止动作 |
| 比较方式 | 同任务与环境运行 A、B，保留任务配对；顺序随机化 |
| 评分器 | 代码检查字段与状态；人工检查政策解释；模型评分仅经校准辅助 |
| 配置冻结 | 模型版本、提示、知识快照、工具、预算和评测器版本 |
| 缺失规则 | 超时与未知结果保留原任务分母，按契约判为未通过并单列 |
| 重复运行 | 预定次数与任务内聚合规则，不将相关重复当独立样本 |
| 发布门槛 | 业务设定最低效果及护栏；本章不提供通用合格率 |

任务集应包含常见任务和风险任务，但二者的权重不同。对抗集用于发现漏洞，不代表生产发生率；均匀抽取类型的评测不能直接推导真实流量完成率。报告要分别给出覆盖结果和适用边界。

## 三、评分器也需要被评测

代码评分器适合可确定检查，如字段白名单、版本、引用可解析、实际状态。它不能单靠引用编号判断政策解释正确。人工评分需要具体量表和校准示例，争议保留双评与裁决。模型评分器可能受语言风格、顺序和候选身份影响，应隐藏方案身份、随机展示顺序并用人工样本检查偏差。

不要要求保存或公开模型私有内部推理来证明正确。可检查的是允许记录的行动、输入输出摘要、证据定位、工具结果与业务状态；敏感内容仍按授权处理。轨迹完整也不等于结果正确。

校准可按“缺失条件、无据主张、错误适用范围、正确拒绝”建立判例。评分器更新后应重算可比较任务或解释断层，不能用更宽松的量表让候选方案显得更好。

## 四、合成夹具：分母与配对比较

**以下数字完全由教学构造，只用于核对统计计算，不是模型运行、真实用户或业务测量。** 设四十张教学任务卡均有预定义结果，A、B 在同一任务上分别判定通过或未通过。

| 配对结果 | 教学任务数 |
| --- | --- |
| A、B 都通过 | 26 |
| 只有 A 通过 | 2 |
| 只有 B 通过 | 6 |
| A、B 都未通过 | 6 |
| 合计 | 40 |

A 通过数为 28，比例为 70%；B 为 32，比例为 80%；绝对差为 10 个百分点，不是“提升 10%”。相对比例变化约为 14.3%，回答不同问题，报告不能混用。

进一步设“都未通过”的六张中有两张 B 超时。若把这两张从 B 分母删掉，就得到 32/38，约 84.2%，人为抬高结果。主分析仍应保留四十张并单列超时。若任务真值未建立，则应报告未评与覆盖缺口，不能自动当通过。

配对比较关注不一致的八张任务：B 赢六张，A 赢两张。零假设下，假定不一致任务偏向哪一方案等可能，采用精确双侧二项检验，得到约 0.289。它不是证实两者等效，也不能仅凭点差宣布改善；样本和不确定性不足以支撑强结论。实际使用该检验还要检查任务独立、配对有效及评分规则预先确定。

## 五、Wilson 区间与独立性

[NIST 统计手册](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)给出二项比例区间方法。对独立二项结果，设通过数为 x、任务数为 n、估计比例 p=x/n，采用 z=1.96 的约 95% Wilson 区间：

```text
center = (p + z² / (2n)) / (1 + z² / n)
half   = z / (1 + z² / n) * sqrt(p(1-p)/n + z²/(4n²))
interval = [center - half, center + half]
```

教学 B 的 32/40 得到约 65.2%–89.5%。区间宽，提醒点估计并不稳定。频率学解释是：在满足假设的重复抽样中，该方法生成的区间按名义水平覆盖真比例；不是对这个固定真比例赋予 95% 概率。

单方案比例区间不等于配对差异区间，不能用两条区间是否重叠替代配对检验。多个任务来自同一用户、工单或文档时，结果可能相关；同任务多次运行也相关。此时需保留聚类结构，采用适合聚类或分层的分析，不能简单将所有运行当独立 n。

## 六、重复运行、污染与可靠性

模型可能一次通过、另一次失败。`pass@k` 关注多次尝试中至少一次成功，`pass^k` 关注多次全部成功；二者服务不同产品承诺。只展示最好一次会掩盖用户第一次运行体验。

为了说明差异，作一个纯数学假设：单次成功概率 0.8，三次独立同分布尝试，则至少一次成功为 1−(1−0.8)³=0.992，全部成功为 0.8³=0.512。**这些不是模型结果，真实尝试可能相关，不能套用独立公式预测产品。** 重复次数、重试成本和用户选择机制也要进入报告。

评测污染包括开发时不断查看保留集、把答案放进提示或知识、评分器接触候选身份、选最好运行。应分开发集、保留集与风险回归集，记录访问和更新。保留集不是永远不变，但更新必须说明原因与可比性。

## 七、失败案例与验收

**失败案例：只报平均总分。** 候选在普通任务提高，却出现跨租户泄露。总分掩盖护栏事故。纠偏是按风险类型报告，硬性边界单独判定；样本零事故也不证明绝对安全。

**失败案例：评分器喜欢长答案。** 候选更冗长，模型评分更高，关键条件却仍遗漏。纠偏是用任务量表、盲评与人工校准，避免把语言偏好当业务质量。

验收报告时复算分母、配对表、超时处理和区间，检查所有版本与真值来源。教学夹具只能通过计算验收，不能通过“模型上线验收”。真实测试还必须在授权目标环境运行。

## 八、工作坊与完成标准

1. 写评测计划和八类任务，每类有真值、正确终态及禁止动作。
2. 为代码、人工、模型评分器分配不同检查责任。
3. 复算教学夹具，解释删超时分母与百分点混用的错误。
4. 写包含区间、配对检验、独立性限制和未测项的报告。
5. 定义真实运行前的授权、版本冻结和保留集管理。

完成需交付任务集规格、评分量表、评测计划和可复算报告；能够区分点差、统计证据、实际价值和安全门槛。真实模型效果、生产代表性和业务改善均不得由本章夹具推导。
