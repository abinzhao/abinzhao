# PRD 与 Agent 交互：把不确定行为写成可验收规格

## 学习目标

本章训练写工程、设计、业务和测试都能使用的需求。学完应能把一句“自动处理工单”拆成用户目标、输入、状态、规则和验收；为不确定性设计澄清、拒绝与接管，而不是只画聊天框和顺利路径。

## 一、PRD 需要约束行为，而非限定每句话

模型输出具有变动性，不适合要求所有回答逐字相同；但用户目标、允许来源、权限、动作、终态和证据标准必须确定。规格可以允许多种合格草稿，同时禁止无证据结论、未经批准写入和虚假成功提示。

聊天只是输入方式。结构化字段适合收集必需信息，证据面板适合核对来源，差异预览适合审批写入，任务记录适合恢复工作。把所有内容塞进消息流，可能让用户错过审批范围或无法发现状态变化。选择界面应依据任务和风险，不依据“AI 产品一定要像聊天软件”。

[OpenAI 工具调用流程](https://platform.openai.com/docs/guides/function-calling)区分建议与实际执行，[Anthropic 评测实践](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)区分轨迹与结果。它们支持 PRD 把“生成”“请求批准”“执行”“确认完成”设计为不同状态；下面的具体交互文案是教学设计，不是厂商规定。

## 二、交付样例：PRD 核心规格

以下为“澄明服务台”教学 PRD，未开发、未测试、未上线。

| 字段 | 已填写样例 |
| --- | --- |
| 需求编号 | `PRD-LAB-01`，受控知识答复草稿 |
| 用户故事 | 作为有读取权限的专员，希望在当前工单中查证政策并获得可编辑草稿，以便核对后继续处理 |
| 入口 | 当前工单的“查证并起草”；仅显式启动，不后台扫描 |
| 前置条件 | 用户登录有效、租户匹配、当前工单可读、知识访问获准 |
| 必需输入 | 问题类别与发生时间；应用注入任务和身份上下文 |
| 主流程 | 校验输入 → 读取授权证据 → 形成草稿 → 显示条件与引用 → 专员编辑或转人工 |
| 输出 | 草稿、适用条件、逐项证据、缺口、状态与下一步 |
| 非目标 | 不外发、不结案、不退款、不变更账户权限 |
| 保留策略 | 不默认永久保存草稿；实际期限与存储范围待治理批准 |
| 成功判定 | 草稿满足任务标准且来源可检查；不以生成结束等同业务结案 |
| 遥测边界 | 记录去内容化任务状态，不默认收集原始问题与全文 |
| 发布依赖 | 知识批准、权限实现、评测、预算与运行手册 |

这份核心规格还不能代替详细需求。设计与工程需要知道字段默认值、是否可编辑、异常分类、取消效果和访问权限；测试需要知道哪些结果算合格。接下来用状态表和验收样例补齐。

## 三、状态、文案与用户下一步

| 状态 | 可见说明 | 可用操作 |
| --- | --- | --- |
| 待输入 | “补充问题类别和发生时间后开始查证” | 填写、取消 |
| 检索中 | “正在读取你有权限访问的有效知识” | 取消；不得显示未确认结论 |
| 待澄清 | “缺少发生时间，无法确认政策版本” | 补充信息、转人工 |
| 草稿就绪 | “草稿未发送，请核对条件和依据” | 编辑、查看证据、重新查证 |
| 无充分证据 | “当前授权知识不足以支持结论” | 查看缺口、转知识负责人 |
| 来源冲突 | “发现同级有效来源冲突，暂不形成确定结论” | 查看冲突、请求核对 |
| 权限失效 | “访问权限已变化，本次任务已停止” | 返回工单；不建议扩大权限 |
| 暂时故障 | “知识服务暂不可用，本次尚未完成” | 预算内重试、人工处理 |
| 已取消 | “已停止后续处理；未发送或修改工单” | 重新开始 |

“已取消”文案只适用于本章的只读能力。如果以后存在已发出的写请求，取消不能保证没有副作用，必须采用第八章的未知结果状态。PRD 要将状态与真实执行条件关联，不把友好文案当实现保证。

生成中可以流式展示尚未确认的草稿，但应明确“内容生成中、未核验”。政策结论未经证据检查前不应被表现为正式结果。首字出现快只是感知指标，用户得到可验收草稿的时间才接近任务价值。

## 四、澄清与证据体验

澄清要针对阻断任务的缺失，而非让用户重复全部上下文。系统已可靠取得工单类别时不应再次询问；缺发生时间时明确为什么需要，以及不提供会怎样。对于无法回答的用户，给人工接管路径，不反复追问直到用户退出。

证据展示应支持检查关键结论：来源名称、版本、适用范围、段落定位和是否仍有效。不要只显示一个绿勾或“已引用”。用户看到来源冲突时应能比较差异；无权查看来源时不得以摘要绕过权限。

写入交互不在本章首版范围，但 PRD 应预留语义边界：草稿按钮不是执行按钮，“建议分类”不是“更新分类”。后续增加写入时，必须显示变更前后值、资源、审批范围与风险，不能复用一个“继续”按钮隐式扩大授权。

## 五、可访问性与错误防护

交互规格需要键盘操作、明确焦点、可读标签和状态播报。不能只用颜色区分“草稿”“已批准”“结果未知”；长任务变化不能不断抢焦点或让读屏重复全部文本。证据面板展开与关闭后，应返回触发位置，避免用户丢失工作上下文。

移动端需要保持核心任务与证据可读，长引用和结构化差异不能造成文档级横向溢出。按钮的触控区域、加载状态和禁用理由应遵循目标产品规范。具体尺寸及浏览器适配由项目规则确认，不因本课程教学原型就宣称满足全部无障碍标准。

错误防护要发生在提交前后。必填校验说明具体缺项；权限失败不引导用户把资料粘贴进聊天绕过限制；重复点击不会创建重复任务；重新查证要说明旧草稿是否失效。取消、重试和转人工都要有真实行为，不能是装饰按钮。

## 六、验收样例与失败案例

```text
验收 AC-LAB-03：缺少发生时间
Given：用户有读取权限，问题类别已填写，发生时间为空。
When：用户启动查证。
Then：进入待澄清状态，说明时间用于判断政策版本。
And：不生成确定政策结论，不写工单，不扩大检索范围。
And：用户可补充时间或转人工；事件只记录缺项类型，不记录全文。
```

这是教学验收语句，不是已执行的测试。每项验收都应明确前置、触发、可观察结果和禁止行为。对模型输出使用语义标准，例如关键条件完整且不新增无据结论，而不是只匹配固定句子。

**失败案例：一个“完成”覆盖所有状态。** 检索完成后界面显示任务完成，用户误以为工单已修改。纠偏是区分检索、草稿、执行和业务结果，按钮与状态使用同一语义。

**失败案例：取消只是关闭窗口。** 后台仍继续执行并保存结果。纠偏是定义取消信号、执行器行为、未完成动作和恢复提示，关闭界面与取消任务分别设计。

验收时让未参与写 PRD 的读者逐条走查正常、缺失、冲突、权限失效、超时和取消路径。读者必须知道自己能做什么、系统做了什么、还没做什么，以及接下来找谁。

## 七、工作坊

1. 将一个模糊需求改成用户故事和核心规格，写清非目标。
2. 为九种状态填写可见文案、允许操作与禁止副作用。
3. 制作低保真界面，至少有输入、草稿、证据和接管四种视图。
4. 写六条验收语句，覆盖边界和失败，不只覆盖顺利流程。
5. 用键盘顺序演练并检查焦点、标签、状态播报和重复提交。

## 完成标准

交付可评审 PRD、状态表、交互文案、界面草图与验收清单。每个状态都有下一步，每个按钮都有明确行为，用户能区分未执行、已执行与未知。原型走查、可访问性和真实模型行为尚未测试时，必须分别标注。
