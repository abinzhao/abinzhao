# 11 · 性能、分包、CI 与真机

## 性能问题先归属到阶段

启动慢可能来自包下载、资源解码、首屏初始化或网络等待；交互慢可能来自同步计算、巨大响应式集合或渲染通信；长时间后卡顿可能来自监听和原生资源泄露。先观察哪一阶段增长，再做最小改动。不能看到一次低端机卡顿就重写为另一种渲染路线，也不能靠隐藏加载动画掩盖任务尚未完成。

标准 Vue、App nvue 与 x 的渲染路径不同，本专题不混用性能保证。Web 性能面板可定位浏览器任务，但小程序逻辑层与宿主渲染通信需要目标工具检查；App 还涉及基座、原生层和 WebView。测量对象包括源码、编译器、生产模式、设备和网络，缺一项就难以解释前后差异。

## 首屏与列表的范围

首页只加载当前需要的服务字段与最小页面资源，不一次性初始化低频地图、相机和管理 SDK。公共常量可以共享，重型依赖按业务入口隔离；动态导入是否被目标打包器真正拆分，要检查产物，不能只看代码写了 import。地图预热也可能涉及权限与采集，性能优化不能越过用户意图。

长列表先分页，再考虑目标允许的虚拟化方案。列表 key 保持稳定，派生字段只计算必要集合，输入变化不序列化全部历史。服务器排序与客户端排序要有一致规则；新增页采用明确游标和去重，不能反复拉取全部记录后前端截取几十条，网络与解析成本仍然存在。

图片按使用尺寸提供资源，避免小缩略图下载巨幅原图。声明展示尺寸减少布局变化，错误和加载状态保留稳定空间；附件压缩在适当线程执行，不阻塞按钮反馈。缓存命中、资源数量与总大小要看真实记录，不使用虚构数据量和性能百分比作为课程结果。

## 用分包隔离低频页面

标准工程在 pages 配置中声明分包。下面例子把帮助页放入低频包，主包仍保留首页。创建对应 `packages/help/guide.vue`，将真实帮助内容与返回动作写入，再从首页按完整路径导航。只写 JSON 而没有文件，无法验证包能加载。[cite:1]

```json
{
  "pages": [
    { "path": "pages/index/index", "style": { "navigationBarTitleText": "预约练习" } }
  ],
  "subPackages": [
    {
      "root": "packages/help",
      "pages": [
        { "path": "guide", "style": { "navigationBarTitleText": "练习说明" } }
      ]
    }
  ]
}
```

```vue
<script setup lang="ts">
function home() { uni.reLaunch({ url: '/pages/index/index' }) }
</script>

<template>
  <view class="page">
    <text class="title">端侧预约练习说明</text>
    <text>记录仅保存在当前设备，不占用商家库存，也未提交服务器。</text>
    <text>清除会删除本设备练习记录；真实预约需要服务器确认。</text>
    <button @click="home">回到练习首页</button>
  </view>
</template>

<style scoped>
.page { padding: 32rpx; display: flex; flex-direction: column; gap: 24rpx; }
.title { font-size: 36rpx; font-weight: 600; }
button { min-height: 44px; margin: 0; }
</style>
```

分包是否减小主包，取决于依赖归属。主包公共入口如果再次导入帮助包的大资源，仍可能把资源带回主包。独立分包有不同依赖约束，不能机械开启。目标包体上限以对应平台当前官方规则为准，不把某个平台的数字复制给 Web、App 和其他小程序。

## 可重复的构建与类型检查

CLI 学习工程先固定依赖与锁文件，再执行当前模板提供的生产构建。`npm ci` 要求已存在对应锁文件，它不会替代首次安装，也不会自动解决不一致依赖。可视化工程使用 IDE 编译器，不应在其根目录猜测 npm 脚本；两条路径分别建立记录。[cite:2]

```bash
# 在官方 vite-ts 学习工程中，先确认本工程脚本
node --version
npm run
npm ci
npm exec --no -- vue-tsc --noEmit
npm run build:h5
npm run build:mp-weixin
```

如果锁文件、类型工具或脚本不存在，应回到模板与安装步骤确认，不在 CI 中临时装 latest 修补。类型检查、生产构建与领域测试分开记录。生产输出还需检查不支持平台的条件代码是否已移除、静态资源路径是否正确、错误提示是否保留；一个成功退出码不代表用户流程已通过。

CI 最低步骤是确定源码与工具、安装锁定依赖、运行领域断言与类型检查、构建目标、保存日志与产物摘要。不要在每次 PR 自动提审或发布；发布需要目标身份与明确确认。私钥和签名凭据由受控系统注入，不能写入教学 YAML、源码或构建日志。

## 测试分层与自动化

纯领域测试检查输入和状态，不依赖页面工具；组件测试检查绑定和事件；平台自动化检查导航、控件与数据；真机检查键盘、权限、网络和生命周期；正式包还检查签名、模块与发布配置。各层通过代表各层证据，不能由一层替代全部。

HBuilderX 的自动化测试插件从四点一零起提供 CLI 接口，这是最低能力条件，不是当前插件版本。安装后先检查当前插件版本与帮助。官方参数表和 Android 示例中，设备及用例文件参数的写法存在不一致，应以本机 `--help` 和实际插件为准，不抄一个未经验证的参数组合。[cite:3]

```bash
# HBUILDERX_CLI 由读者设置为实际 IDE cli 可执行文件路径
"$HBUILDERX_CLI" uniapp.test --help
```

自动化环境要具备目标工具、测试插件和设备连接，部分平台还需单独权限或驱动。先用一个页面与一个按钮验证工具链，再扩大用例，不把设备连接失败说成应用回归。自动化 API 版本同样固定，断言当前页面与业务状态，不只断言点击命令发送成功。

## 完整项目的验收矩阵

预约至少测正常创建、重复提交、已过时段、取消幂等、恢复、坏缓存、满额和写入失败。跨端再增加输入事件、日期 picker、系统字号、键盘遮挡、前后台切换和存储实际行为。真实服务器接入后增加身份切换、库存冲突和写请求超时未知结果，不能沿用本地同步成功假设。

每条记录写目标系统、客户端、工具、编译器、模式、输入动作、预期结果和实际结果。模拟器没有真实定位或照片权限时标记能力未验证；Web 浏览器不代表 Android App 的 WebView；标准基座不代表正式签名包。未执行的平台写待验证，不为了表格完整填入通过。

## 真机与发布路径

微信检查真实 AppID、合法域名、隐私声明、体验版本与目标客户端。App 检查模块、用途说明、包标识、签名、地图和 OAuth 配置，在实际签名包测试；iOS、Android 和 HarmonyOS 分别记录。Web 检查 HTTPS、静态资源、深链接回退、缓存和浏览器目标，开发代理不能替代部署网络。

提审前清点第三方 SDK 的初始化、采集和权限，不在用户同意前启动不必要任务。版本升级后核对隐私清单与实际网络，审查是否有调试接口、凭据或测试开关进入产物。用户数据不是性能测试素材，应使用固定公开教学输入或经允许的脱敏数据。

## 测量与排错的顺序

先做一次冷启动和一次暖启动，区分缓存影响；再在相同设备与网络重复，记录波动而不是只选最好一轮。优化后按同样条件复测，确认变化来自改动而非工具升级或网络。没有实际计时就不写数值结果，日志缺失也不宣称达到某个阈值。

包仍大先看产物依赖和静态资源，输入卡顿先看同步任务与深监听，返回后变慢先看重复订阅，正式包能力失效先看基座差异与签名配置。每次只改影响该阶段的必要代码，再回归核心流程。性能改善不能以丢失错误提示、关闭校验或取消隐私判断为代价。

## 实践与验收

基础作业给低频说明页建立分包，检查主包资源归属与冷启动路径，验证分包失败能返回。进阶作业把第十二章纯逻辑命令接入独立学习工程的 CI，随后分别执行 Web 与微信生产构建；设备不存在时明确记录未执行，不把构建输出替代设备结果。

发布作业是建立逐端检查表，包括源码、工具、依赖、域名、隐私、设备与正式包。每项附命令或人工操作及证据路径。完成标准是能复跑和追踪，而不是所有格子都写通过。本专题没有运行 HBuilderX 平台自动化、App 打包、微信提审或商店发布；实际发布仍需要目标资格、设备与明确授权。
