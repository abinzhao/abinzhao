# 个人博客「沉浸光感」视觉重构设计

## 目标

将现有个人网站重构为“以内容为核，光效为衬”的沉浸光感体验，在不改变真实内容、静态发布方式和核心路由的前提下，建立统一的浅色与深色视觉系统。

深色首页首屏使用 3D 星体与磁场粒子形成品牌视觉签名；其他页面和首页后续内容降低光效强度，优先保证阅读、导航和信息层级。

## 现状与证据

| 已确认事实 | 证据 | 设计影响 |
|---|---|---|
| 站点使用 Next.js App Router，并通过静态导出发布到 GitHub Pages | `next.config.ts`、`.github/workflows/deploy-pages.yml` | 新设计不得依赖服务端运行时 |
| 首页右侧使用轨道式能力图 | `app/page.tsx`、`components/AbilityMap/index.tsx` | 由首页专用星体场景替换 |
| 当前只有 1 篇公开文章和 5 个公开项目 | `content/articles/`、`content/projects/` | 不伪造精选文章、阅读量、评论、分页和相关推荐 |
| 内容由 MDX 和 Zod 在构建期读取、校验 | `lib/content.ts` | 保留现有内容模型和读取链路 |
| RSS、Sitemap、Robots 和静态路由已上线 | `app/rss.xml/route.ts`、`app/sitemap.ts`、`app/robots.ts` | UI 重构不得造成发布与 SEO 回归 |
| 旧视觉样式主要集中在全局样式文件 | `app/globals.css` | 实施时按组件职责拆分新增逻辑，避免无关结构重构 |

## 范围

### 当前方案

- 建立浅色与深色主题，默认跟随系统偏好，并持久化用户选择。
- 重构首页、文章列表、文章详情、项目列表、项目详情、关于页、联系页和全站导航。
- 在深色首页首屏加入真实 3D 星体、磁场曲线与粒子。
- 在浅色首页首屏使用 CSS 静态柔光体，不初始化 WebGL 场景。
- 增加滚动导航玻璃效果、内容进入动画、环境光和组件交互反馈。
- 增加文章目录、代码块复制增强等只依赖现有内容的能力。
- 完成桌面、平板、移动端响应式和无障碍降级。

### 范围边界

- 不修改 MDX frontmatter、RSS、Sitemap、Robots 和静态导出协议。
- 不引入阅读量、评论后端、分析服务或用户系统。
- 不为满足版式数量而生成虚构文章、项目、经历、年份或指标。
- 不让 3D 场景贯穿全站，也不在文章正文区域持续运行粒子动画。
- 不进行与本次视觉重构无关的内容系统或工程结构重写。

## 设计原则

### 内容优先

光效只用于首页视觉焦点、可交互反馈和内容层级。普通正文保持纯净，不使用发光正文、动态背景或玻璃容器。

### 物理一致

光晕使用柔和衰减，星体明暗由材质和光源形成，玻璃表面区分透光、高光和阴影。避免纯色描边发光、随机雪花粒子和无来源的霓虹效果。

### 强弱分层

全站由两层视觉系统组成：

1. 系统层：主题变量、环境光、玻璃导航、分区光条和交互反馈。
2. 品牌层：只在深色首页首屏出现的 3D 星体与磁场粒子。

离开首屏后逐步降低亮度、动画密度和空间效果，使阅读重新成为主要任务。

## 视觉系统

### 色彩变量

| 语义 | 浅色模式 | 深色模式 |
|---|---|---|
| 主背景 | `#FAFBFF` | `#0A0E1A` |
| 次级背景 | `#F0F2F8` | `#151929` |
| 主标题 | `#1A1D2E` | `#E8EAF6` |
| 正文 | `#3D4259` | `#B0B3C5` |
| 辅助文字 | `#6B708C` | `#7A7F99` |
| 强调色 | `#6366F1` | `#8B8DF9` |
| 主环境光 | `rgba(120, 140, 255, 0.12)` | `rgba(100, 120, 255, 0.18)` |
| 辅助环境光 | `rgba(255, 180, 140, 0.08)` | `rgba(140, 200, 255, 0.10)` |
| 卡片内高光 | `rgba(255, 255, 255, 0.60)` | `rgba(255, 255, 255, 0.08)` |

所有颜色、间距、圆角、阴影、光效和动画参数通过 CSS 变量管理。组件只使用语义变量，不直接复制主题色值。

### 字体与排版

- 标题优先使用 Inter 或兼容的系统无衬线字体，避免引入来源和授权不明确的字体。
- 标题层级为 `48px / 36px / 28px / 22px`，小屏按比例收缩。
- 正文基准字号为 `17px`，行高为 `1.7`，段间距为 `24px`。
- 代码使用 Fira Code 或等宽系统字体，字号为 `15px`。
- 文章正文最大宽度为 `800px`，不因右侧目录改变正文行宽。

### 间距与栅格

- 基准间距单位为 `8px`。
- 桌面内容区最大宽度为 `1200px`，采用 12 栏布局。
- 模块基准间距为 `80px`，卡片间距为 `32px`，内容内边距为 `24px`。
- 移动端使用单栏布局，左右边距为 `16px`。

## 页面结构

### 首页

首页按视觉强度从高到低组织：

1. `ImmersiveHero`：左侧展示真实个人定位、简介和行动入口，右侧展示主题对应的视觉场景。
2. `FeaturedContent`：使用现有真实文章与项目组成非对称布局，不强制凑齐 3 篇文章。
3. `LatestWriting`：按发布时间倒序展示文章；只有存在多个分类时才显示分类筛选。
4. `SelectedWork`：展示真实项目，减少装饰，突出项目标题、方向和入口。
5. 页脚：保留版权和公开社交入口，悬停光效不替代文字标签和焦点状态。

旧网格背景、能力轨道图、薄荷绿信号点和工业控制台式装饰不再保留。

### 文章列表页

- 文章卡片在桌面、平板和移动端分别使用 3 栏、2 栏和 1 栏布局。
- 卡片只展示真实标题、摘要、发布时间、标签和主题。
- 不显示没有数据源的阅读量。
- 分类少于两个时不显示筛选栏，避免无效控件。

### 文章详情页

- 正文使用最大宽度 `800px` 的单栏阅读布局。
- 标题区可使用低强度弥散光，正文区域不使用持续光效。
- 桌面端仅在文章存在多个二级标题时显示右侧悬浮目录。
- 代码块使用深色背景和左侧强调光条；复制按钮在悬停或键盘聚焦时显示。
- 当前没有真实数据支撑时，不显示评论、阅读量、分页和相关推荐。

### 项目页

- 项目列表与详情沿用现有真实内容模型和路由。
- 视觉重构只调整层级、留白、卡片和链接反馈。
- 公开仓库没有披露的信息继续明确标记为不可用，不通过视觉文案补全。

### 关于页

- 左侧展示个人介绍、技术方向和技能标签。
- 右侧使用“能力演进”结构组织已验证内容。
- 只有存在可靠时间证据时才显示年份时间轴，不推断任职经历和项目日期。

### 联系页

- 保留 GitHub、掘金等已验证公开入口。
- 联系表单在没有真实服务和隐私说明时继续保持禁用或不渲染。

## 组件边界

| 组件 | 职责 | 依赖与边界 |
|---|---|---|
| `ThemeProvider` | 初始化主题、响应系统偏好、持久化用户选择 | 不依赖页面内容；存储失败时退回系统主题 |
| `ThemeToggle` | 切换主题并提供可访问名称和焦点反馈 | 只调用主题接口 |
| `SiteHeader` | 控制导航、移动菜单和滚动玻璃状态 | 不管理页面数据 |
| `AmbientLight` | 渲染纯装饰环境光 | `aria-hidden`，不接收内容 |
| `RevealSection` | 统一内容进入动画 | 响应 reduced-motion，不改变布局 |
| `GlassCard` | 提供受约束的玻璃表面样式 | 只用于卡片和明确的浮层层级 |
| `CelestialScene` | 渲染深色首页的星体、磁场和粒子 | 独立客户端组件，仅首页动态加载 |
| `TopicFilter` | 从真实文章主题生成筛选项 | 分类不足时不渲染 |
| `ArticleToc` | 从真实标题生成目录并高亮当前章节 | 标题不足时不渲染 |
| `CodeBlockEnhancement` | 提供复制操作和可见反馈 | 失败时保留原始代码内容 |

`components/AbilityMap` 由 `CelestialScene` 替换。是否删除旧组件由实施阶段根据引用检查决定，不保留无引用兼容层。

## 主题与状态流

主题切换只提供浅色和深色两个明确状态。主题初始化顺序为：

1. 读取用户已保存的明确选择。
2. 没有明确选择时读取 `prefers-color-scheme`。
3. 将结果写入根节点 `data-theme`。
4. CSS 变量、导航和首页场景响应同一主题状态。

用户未手动选择主题时，页面响应系统主题变化；用户手动切换后，以已保存选择为准。主题初始化脚本在首屏绘制前执行，避免明暗主题闪烁。`localStorage` 不可用时不抛出页面级错误，直接使用系统主题。

## 星体与磁场场景

### 技术方案

使用原生 Three.js 实现真实球体、材质和光照，并通过动态导入限制到首页深色 Hero。选择原生 Three.js 而不是 React Three Fiber，以减少运行时抽象和额外依赖；不使用 Canvas 2D 假 3D，以保证球体明暗和空间层次可信。

### 行为

- 星体是场景唯一视觉主体，保持低速自转。
- 磁场粒子沿预计算曲线聚散，不执行高成本实时物理模拟。
- 鼠标和触控只产生轻微相机偏移，不移动文本内容。
- 首屏文字、导航和行动按钮不等待 Three.js 加载。
- 场景不可获取焦点，不拦截指针和键盘操作。

### 性能边界

- 限制设备像素比，避免高分屏产生过高 GPU 开销。
- 粒子数量按视口分级，桌面端使用完整密度，平板端降低密度。
- 通过 Page Visibility API 在页面不可见时暂停渲染，通过 Intersection Observer 在场景离开首屏后暂停渲染。
- 浅色主题、移动端、reduced-motion 和 WebGL 不可用场景不初始化完整动画。

## 光效与动效

- 首屏左上角和右下角使用柔和环境光斑，桌面直径上限为 `600px`。
- 环境光视差上限约为 10%，只通过 `transform` 实现。
- 模块之间使用低对比度光条，不使用高亮实线分隔。
- 常规交互动效时长为 `0.2s–0.4s`，缓动曲线为 `cubic-bezier(0.25, 0.8, 0.25, 1)`。
- 内容进入动效为 `opacity` 与 `translateY(20px)`，时长为 `0.5s`，每个模块只执行一次。
- 动画只使用 `transform` 和 `opacity`，不通过 `top`、`left` 改变布局。

## 核心组件视觉

### 导航

- 页面顶部默认透明。
- 滚动后使用 `blur(12px)` 毛玻璃背景，并添加 1px 玻璃边缘反光。
- 导航项悬停或聚焦时出现 2px 强调光条，同时保留文字和形状反馈。
- 不支持 `backdrop-filter` 时使用不透明度更高的纯色背景。

### 文章卡片

- 使用单层半透明表面、16px 圆角、细边框和顶部折射高光。
- 悬停时最多上浮 8px，并增强阴影和标题内发光。
- 键盘聚焦提供与悬停等价的边框和阴影反馈。
- 移动端不依赖悬停才能读取内容或访问操作。

### 按钮

- 主按钮使用强调色柔和渐变和可控阴影，悬停缩放上限为 `1.03`。
- 次按钮使用透明背景和强调色边框。
- 所有按钮最小触控尺寸为 `44px`，焦点轮廓不能被阴影覆盖。

## 响应式规则

| 视口 | 布局与光效 |
|---|---|
| `>= 1024px` | 完整 12 栏布局、桌面导航、完整星体磁场、文章 3 栏 |
| `768px–1023px` | 间距缩小约 20%、环境光透明度降至约 0.08、文章 2 栏 |
| `< 768px` | 单栏布局、汉堡导航、关闭环境光视差、光斑缩小至约 300px、文章 1 栏、使用静态星体 |

任何视口不得产生横向溢出。右侧文章目录只在空间足够且不会压缩正文行宽时显示。

## 无障碍

- 所有正文、标题、按钮和链接满足 WCAG AA 对比度要求。
- 发光效果不作为唯一的状态表达，同时使用下划线、边框、位移或形状变化。
- 语义化 HTML、标题层级、导航 `aria-label` 和图片替代文本保持完整。
- 主题切换、移动菜单、复制按钮和筛选控件支持键盘操作。
- 3D 场景和环境光标记为装饰，不进入辅助技术阅读顺序。

启用 `prefers-reduced-motion` 时：

- 停止星体自转、粒子运动、视差和所有位移动画。
- 保留静态星体、环境光和必要的透明度反馈。
- 页面功能、内容层级和交互状态不因动画关闭而缺失。

## 数据流与异常降级

MDX 内容继续在构建期读取并校验。页面组件只消费已发布的真实 frontmatter；主题和星体场景不修改内容数据。

| 场景 | 降级行为 |
|---|---|
| WebGL 初始化失败 | 展示静态 CSS 星体和环境光 |
| JavaScript 未加载 | 内容、导航链接和静态路由仍可使用 |
| 没有文章或项目 | 使用现有 `ContentEmptyState` 明确提示 |
| 分类不足 | 不渲染筛选栏 |
| 目录标题不足 | 不渲染悬浮目录 |
| `localStorage` 不可用 | 使用系统主题 |
| 不支持 `backdrop-filter` | 使用纯色半透明背景、边框和阴影 |
| reduced-motion | 使用静态视觉并关闭位移动画 |
| 移动端 | 不初始化 WebGL，使用静态星体 |

所有降级保持真实内容完整，不展示伪造值或含义不明的占位数据。

## 测试与验收

### 自动化测试

- 单元测试覆盖主题选择优先级、分类生成和目录显示条件。
- 组件测试覆盖主题切换、导航滚动状态、筛选操作和关键降级。
- E2E 覆盖首页、项目、文章、关于和联系页面。
- E2E 验证主题切换与持久化、移动导航、键盘操作和 reduced-motion。
- E2E 验证桌面、平板、移动端没有横向溢出。
- 现有 RSS、Sitemap、Robots 和静态详情路由继续通过验证。

### 浏览器验收

使用外部 Chrome 和 Chrome DevTools 完成以下视口检查：

- `1440px`：完整星体磁场、非对称首页布局和桌面目录。
- `900px`：双栏内容、降低环境光强度和稳定导航。
- `390px`：单栏内容、汉堡导航、44px 触控目标和静态星体。

验收时确认：

- 控制台无运行时错误。
- 网络请求没有意外 4xx 或 5xx。
- 首屏文字不等待 Three.js 加载。
- 页面没有横向溢出和明显布局偏移。
- 正文行宽、行高、颜色对比和焦点状态符合本规范。
