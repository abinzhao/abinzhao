# 全站空间压缩与本地 AI 增强 · 全面需求（design）

## 背景与输入

- 输入形态：产品视角改造要求 + 当前问答页截图 + 当前仓库源码与运行结果。
- 已确认决策（用户回复“全部按推荐”）：
  - 采用纯浏览器检索与证据式回答，不运行本地或云端大模型，不调用任何推理服务。
  - 保留旧版模型会话并标记为“旧版记录”，后续问题统一由本地知识引擎回答。
  - 无需前端灰度，静态站点一次性替换；异常通过 Git 回滚，不保留违反本次约束的旧模型路径。
- 截图可见问题：桌面端主导航与独立页面标题区连续占据较大首屏空间，问答工作区被整体下推。
- 浏览器实测基线：
  - 1440×900：全局导航高 64px；博客首张内容卡片从 `y=424px` 开始；文章正文从 `y=415px` 开始。
  - 390×844：全局导航高 60px；博客首张内容卡片从 `y=477px` 开始；文章正文从 `y=452px` 开始。
  - 390×844 问答页：工作区从 `y=305px` 开始，输入框位于 `y=895px` 至 `1004px`，首屏不可见。
- 本地问答现状：
  - 仅检索 44 篇已发布文章的标题、摘要和标签；仓库中的 49 个 Markdown 还包含 5 个列表或专题索引页，约 372KB 正文及 338 个二、三级标题章节尚未进入问答语料。
  - 中文查询按连续二元字切分并做包含匹配，没有同义词、意图识别、章节级检索、置信度或结果去重。
  - 会话历史只用于展示；追问不会继承上轮主题、来源或实体。实测先问“CSS 布局怎么学习？”，再问“那它和 Grid 有什么区别？”，第二问直接返回无结果。
  - “模型对话”会调用 OpenAI 兼容端点，允许 HTTPS 远程地址，与本需求禁止云端模型服务的约束冲突。
- 当前工程基线：类型检查通过，27 项单元/构建测试通过，静态构建通过。

## 需求全景

本次改造以“首屏优先、内容优先、本地可信”为主线：保留全局导航、页面身份、筛选、主题切换等必要入口，但将导航和标题区压缩为统一密度体系；问答页移除独立大标题横幅，直接进入可用工作区。AI 模块不再提供远程模型地址、密钥或云端调用能力，改造成浏览器内的站内知识引擎，通过章节级全文索引、意图分类、上下文补全、证据式回答和低置信度澄清提升精准度，并扩展文章总结、概念对比、学习路线、排查清单和围绕本文提问等本地能力。

明确不做：

- 不接入、不代理、不配置任何云端大模型、Embedding、搜索或分析服务。
- 不把“智能”包装成无来源的开放式生成；本地答案必须能追溯到站内内容。
- 不为压缩空间删除页面主导航、主题切换、筛选、文章标题、面包屑语义或无障碍标签。
- 不改造正文内容、项目数据、文章排序和现有视觉主题。
- 不新增后端、数据库、账号系统或跨设备同步。

### [Story 2] 完全本地的知识问答引擎

- **落点 URL**: https://abinzhao.github.io/abinzhao/chat/

- [x] [feature-2-local-corpus] 建立章节级本地知识语料
  - 做什么：构建时解析博客与专题 Markdown，将标题、摘要、标签、章节标题、正文段落、列表和必要代码标识切分为可检索知识块。
  - 关键行为 / 范围：
    - 每个知识块携带文章、专题、章节锚点、内容类型、发布日期和系列顺序。
    - 正文按语义节点切块，不用字符串截断破坏段落或代码结构。
    - 代码块低权重索引关键标识符，不作为无上下文的主要回答文本。
    - 草稿和未发布内容不进入索引。
  - 验收点：
    - 每个索引块都能跳转到真实文章或章节锚点。
    - 内容新增、删除或标题变化后，构建结果自动更新，不需手工维护关键词表。
    - 索引只由站内 Markdown 生成，不读取网络内容。
  - **灰度归属**：无需灰度（用户确认静态站一次性替换）。

- [x] [feature-2-ranking] 提升中英文混合检索与排序精准度
  - 做什么：使用本地全文检索排序，支持中文分词回退、英文技术词、前缀、轻量模糊匹配、字段权重、同义词和多样性去重。
  - 关键行为 / 范围：
    - 标题、章节标题、标签权重大于正文；完整短语高于分散关键词。
    - 同一文章多个相邻章节命中时做去重，避免前四条来源全部来自同一局部。
    - 支持 `Grid`、`CSS Grid`、`网格布局` 等可控同义表达，但同义词表仅维护站内稳定技术术语。
    - 结果携带原始得分与归一化置信度，供回答策略使用。
  - 验收点：
    - 固定评测集中 Top-3 召回率不低于 85%，MRR 不低于 0.75。
    - 44 篇现有已发布文章规模下，首次查询 P95 不高于 150ms，后续查询 P95 不高于 50ms。
    - 空查询、停用词查询和明显站外问题不会返回随机高分文章。
  - **灰度归属**：无需灰度（用户确认静态站一次性替换）。

- [x] [feature-2-intent] 本地意图识别与结构化回答
  - 做什么：在浏览器内识别资料查找、概念解释、概念对比、学习路线、问题排查、内容总结六类核心意图，并选择对应回答模板。
  - 关键行为 / 范围：
    - 资料查找：输出最相关资料及命中原因。
    - 概念解释：提取定义、关键点和适用场景，并逐项引用来源。
    - 概念对比：分别检索两个实体，按共同维度并列差异；证据不足时明确缺口。
    - 学习路线：优先使用专题的章节顺序，补充前置知识和下一步阅读。
    - 问题排查：从站内检查清单、异常处理和工具章节提取有顺序的排查步骤。
    - 内容总结：按章节标题与关键句生成提纲式摘要，不编造原文没有的结论。
  - 验收点：
    - 预置意图评测集中分类准确率不低于 90%。
    - 所有事实性回答均附至少一个可点击来源；来源不足时进入澄清或无答案状态。
    - 不使用 `v-html` 渲染用户输入或回答正文。
  - **灰度归属**：无需灰度（用户确认静态站一次性替换）。

- [x] [feature-2-context] 支持多轮追问的上下文承接
  - 做什么：每个会话保存上一轮意图、主题实体、来源集合、范围过滤和待澄清项，识别“它、这个、前者、继续、再详细点”等追问。
  - 关键行为 / 范围：
    - 追问只继承当前会话最近的有效主题，不跨会话串联。
    - 代词明确时补全上一轮实体；存在两个候选实体时先让用户选择。
    - 用户显式切换新主题时清空旧主题权重，但保留可见历史。
    - 上下文仅保存在浏览器会话数据中，不发送到网络。
  - 验收点：
    - 先问“CSS 布局怎么学习？”，再问“那它和 Grid 有什么区别？”时，能识别为布局主题下的对比追问。
    - 固定追问评测集中上下文实体解析准确率不低于 85%。
    - 新会话不继承旧会话来源或主题。
  - **灰度归属**：无需灰度（用户确认静态站一次性替换）。

- [x] [feature-2-confidence] 建立低置信度与冲突处理
  - 做什么：按检索分数、来源覆盖和意图完整度决定直接回答、请求澄清或明确无答案。
  - 关键行为 / 范围：
    - 高置信度：输出结构化答案与章节来源。
    - 中置信度：先给最可能的理解，再提供 2 至 3 个可选方向。
    - 低置信度：明确说明站内没有足够资料，不输出貌似合理的技术结论。
    - 来源间表述不一致时并列展示，不自行裁决为单一事实。
  - 验收点：
    - 无答案评测集中，错误硬答率不高于 5%。
    - 每条回答显示“高 / 中 / 资料不足”三级可信状态之一。
    - 任何来源链接都必须属于博客或专题页面。
  - **灰度归属**：无需灰度（用户确认静态站一次性替换）。

- [x] [feature-2-no-cloud] 移除全部模型服务配置与网络推理路径
  - 做什么：删除远程模型地址、模型名、访问密钥、OpenAI 兼容请求、SSE 流式解析以及相关说明，问答模块只消费随站点发布的本地静态知识数据。
  - 关键行为 / 范围：
    - 不再显示“模型设置”和“模型对话”入口。
    - 不再接受任意服务地址、访问密钥或模型名。
    - 问答过程中不发起跨域 XHR、Fetch、WebSocket 或 EventSource。
    - GitHub 外链仍可作为普通用户导航，不属于 AI 数据请求。
  - 验收点：
    - 生产环境问答全流程的网络记录中不存在跨域数据请求。
    - 源码、文档和测试不再出现 OpenAI、Ollama、API key、`chat/completions` 等运行配置说明。
    - 离线模式下，已加载的问答页可以继续完成检索、追问、复制、导出和历史读取。
  - **灰度归属**：无需灰度（用户确认静态站一次性替换）。

## 规格摘要

### A. 入口与触发

- 全局入口继续为主导航“智能问答”和全站悬浮入口；问答页自身隐藏重复悬浮入口。
- 文章新增“围绕本文问”入口；仅已发布的博客与专题章节显示。
- 问答页默认进入全站范围；从文章进入时默认当前文章范围。

### B. 主流程

1. 用户进入问答页或从文章入口跳转。
2. 本地懒加载知识索引并恢复合法会话。
3. 用户输入问题或选择快捷动作。
4. 系统识别意图、补全当前会话上下文、检索章节并计算置信度。
5. 高置信度输出结构化答案；中置信度给出方向选择；低置信度明确资料不足。
6. 用户继续追问、打开来源、复制或导出；全流程不请求云端服务。

### C. 核心文案

- 页面标题：`智能问答`
- 本地状态：`完全本地 · 内容不上传`
- 默认输入提示：`输入问题，检索本站知识…`
- 索引加载：`正在准备本地知识库…`
- 无答案：`本站暂时没有足够资料回答这个问题。`
- 澄清提示：`你更想了解哪一部分？`
- 存储不可用：`浏览器无法保存会话，刷新后记录可能丢失。你仍可导出当前会话。`

### D. 选项与默认值

- 来源范围：`全站`（默认）、`博客`、`专题`、`当前文章`（仅携带文章上下文时显示）。
- 快捷动作：`找资料`（默认）、`总结`、`对比`、`学习路线`、`排查清单`。
- 可信状态：`高`、`中`、`资料不足`。

### E. 初始化与兜底

- 首次进入：全站范围、找资料意图、空会话。
- 索引加载失败：保留输入内容，显示失败状态和重试入口，不回退到网络服务。
- 本地存储失败：当前页继续使用，停止持久化并提供导出。
- 当前文章标识无效：回退到全站范围，并提示限定来源已失效。

### F. 二次操作与状态

- 会话可新建、选择、删除、复制和导出；删除仍为即时操作，后续实现时应增加可撤销窗口或二次确认，沿用当前站点交互风格。
- 回答状态：`准备索引`、`检索中`、`已完成`、`资料不足`、`失败`。
- 本地检索应快速完成，不模拟流式打字；只在真实计算期间显示加载状态。

### G. 异常处理

- 采用本地场景适配后的标准行为：保留输入、提供重试、不静默失败。
- 网络断开不影响已加载问答；若首次索引资源尚未加载，明确提示需要完成本站静态资源加载。
- 数据损坏时跳过单条会话或单个知识块，不清空全部历史。
- 大数据量按最多 30 会话、每会话 100 条消息、最多展示 8 个来源限制。

### H. 权限与隐私

- 所有访客均可使用，无账号、角色和租户差异。
- 问题、上下文和会话只存在于当前浏览器内存或本地存储。
- 不采集问答埋点，不发送使用数据。

## 灰度策略

### 需求级前端灰度

- **控制方**：无需灰度。
- **确认来源**：用户回复“全部按推荐”。
- **原因**：当前产品是个人静态站，无远程配置基础设施；旧模型路径允许云端请求，违反本次硬约束，不作为回退路径保留。
- **发布方式**：布局与本地问答能力一次性替换；异常通过 Git 回滚到前一稳定版本。
- **覆盖范围**：全部 Feature。
- **落地约束**：不得新增 localStorage 灰度 key、远程 feature flag 或双轨 UI。

## 后端接口支持

无。

本需求全部基于静态构建产物、浏览器计算和浏览器本地存储；禁止新增后端代理、模型网关、Embedding 服务、远程搜索和遥测接口。

## 手工操作与交付清单

无外部平台、CI 路由、域名、后端或模型服务配置。

若技术方案采用新的本地开源依赖，只允许通过包管理器更新直接依赖和锁文件，并在实施时记录：

- 运行时体积；
- 许可证；
- 浏览器兼容范围；
- 是否仅用于构建阶段；
- 对现有静态部署的影响。
